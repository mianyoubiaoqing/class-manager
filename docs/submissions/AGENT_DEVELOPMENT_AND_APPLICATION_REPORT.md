# 班级助手开发与应用报告

本报告介绍面向中小学教师的班级助手开发方案和当前验证情况。作品用于减少班级资料在多个表格和页面之间重复整理的操作；真实教学成效需要通过试用记录补充。

## 开发背景

教师需要维护名单、点名、考试成绩、座位和值日，同时准备教学资料和学生阶段总结。不同任务重复选择学生、录入信息和查找文件，会增加操作负担。本项目以一份班级资料供多项业务共用为基础，提供本地工作台和智能助手。

## 设计与开发

桌面程序采用 Electron、React、TypeScript 和 SQLite。学生身份与班级归属在本地维护，名单及成绩导入先核对再保存；已有成绩更正保留旧版本。

首页按照教师日常任务提供直接入口。名单以列表呈现，学生档案在详情小窗中汇集基本资料、成绩、点名与成长记录。教学资料可从文件或指定文件夹读取，选择内容后用于备课，结果支持 Word 和 PPT 导出。

在线生成支持国产模型供应商配置。程序在本地计算统计事实，教师选择所需内容，再让模型生成解释、教案或总结草稿。数据修改和正式入档经过教师核对。

开发过程使用生成式人工智能辅助梳理需求、编写代码、设计界面、定位缺陷和整理文档。源码、提示词、自动化测试和专项验收记录保留在交付的完整源码中，可用于复现与检查。人工审核仍需核对实现、实际运行和生成内容。

## 应用过程与当前验证

验证场景包括创建班级、导入名单与成绩、上课点名、第二次考试、学生成绩比较、成长记录及备课课堂流程。新版共享资料流程在隔离的合成数据目录中通过真实桌面界面和 SQLite 完成，确认重启后资料保留。

客户端反馈指出旧界面入口深、说明多、部分操作不易理解。后续迭代采用任务卡片、直接班务导航和列表详情结构，并将教师使用文档与开发、比赛材料分开。

现有测试证明本机合成场景中的功能衔接和部分异常恢复，不等于真实学校环境或所有文件格式都已验收。没有开展可量化的教师时间节省研究，也未取得可报告的学生成绩提升数据。

## 创新与反思

作品把本地确定性业务和在线生成分开处理，通过统一学生身份减少重复准备名单。学生档案将不同任务的结果集中展示，教师可以从同一学生继续查看成绩、点名或总结依据。

迭代中发现，仅有完整功能和自动化测试不足以证明易用性。需要让零基础教师按自己的日常任务完成操作，核对入口、反馈和文档是否一致。模型建议不能替代教师判断；只有汇总分数时，不能据此确定具体知识点薄弱原因。

后续应在授权的真实试用中记录任务耗时、操作失败、用户理解和教学使用效果，再据此完善产品与应用报告。
