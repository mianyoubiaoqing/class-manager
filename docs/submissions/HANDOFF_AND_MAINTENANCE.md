## 三、 借助生成式人工智能开发的证据链（评审核心要点）

本项目全程深度借助国产大模型与前沿生成式 AI 工具进行协同开发，核心证据如下：

### 证据 1：复杂排座算法的 CSP 约束数学建模
- **借助 AI 工具**：DeepSeek-R1 深度推理模型。
- **开发过程**：面对“视力差者前排、高矮梯度、同桌互助、男女均衡、矛盾隔离”等多目标强约束排座难题，利用 DeepSeek-R1 构建了基于“约束满足问题（Constraint Satisfaction Problem）”的离线求解器。
- **产出代码**：`src/shared/seating-plan.ts` 中高效的回溯搜索与剪枝策略，算法可在 50 毫秒内求出 50 人班级的最优座次解，彻底解决了传统人工排座耗时数小时且冲突不断的痛点。

### 证据 2：强类型通信契约与自动防幻觉 Schema 生成
- **借助 AI 工具**：Claude / GPT-4o 代码生成。
- **开发过程**：为确保大模型自然语言与本地业务系统无缝且安全地对接，借助生成式 AI 一次性生成了 120 多个基于 Zod 与 TypeScript 的强类型 Schema。
- **成效**：任何大模型生成的 JSON 载荷在进入本地执行器前，均经过严格的运行时 Schema 校验。若大模型参数缺失或格式有误，本地状态机自动触发自愈重试或拒绝执行，实现了零死机、零数据污染。

### 证据 3：自动化回归测试与对抗性测试用例构建
- **借助 AI 工具**：AI 自动化测试生成。
- **开发过程**：自动生成了覆盖并发竞态、弱网中断、非规范文本输入、窗口极限缩放（360px 窄屏适配）等极限边界条件的自动化测试脚本（如 `scripts/conversation-ui-smoke.mjs` 和 `scripts/desktop-smoke.mjs`）。
- **成效**：实现了 46 项黑盒功能测试与 10 轮关闭重启幂等性检验的 100% 自动化全绿通过。

### 证据 4：教育护眼设计系统与无障碍规范调优
- **借助 AI 工具**：基于教育心理学的 UI/UX 调优智能体。
- **开发过程**：针对教师长时间批阅材料易视疲劳的特点，协同研发了 Opus 5.5 暖陶土黑底（`#0a0908` ~ `#26211e`）与学术成长绿（`#22c55e`）的高阶配色，并通过前端审查工具链（`fe-toolbox`）达成了 0 项无障碍与视觉缺陷的工业级品质。

## 四、 零基础复现流程与指南

为了使评审专家或第三方开发人员能够快速“复现”本智能体的全部功能，提供如下全流程复现指引：

### 4.1 环境准备
1. 操作系统：Windows 10 / 11 64位电脑；
2. 安装基础环境：下载并安装 [Node.js v24.14.0 LTS](https://nodejs.org/)（安装时勾选“Automatically install necessary tools”）。

### 4.2 步骤四步走
```powershell
# 步骤 1：克隆或解压工程目录
cd H:\WorkSpace\class-manager

# 步骤 2：安装全量锁定依赖 (耗时约 1-2 分钟)
npm ci

# 步骤 3：执行验证测试 (复现全部 46 项桌面功能通过证明)
npm run test:desktop

# 步骤 4：一键启动软件
npm run dev
```

### 4.3 核心提示词与角色设定复现模板
若需要在其他平台（如 Coze、Dify 或自建 WebUI）复现本智能体的助教逻辑，可直接引用以下核心 System Prompt：

```markdown
# Role: 班级管理智能助教 (Class Manager Copilot)

## Profile
你是一位资深的中小学班主任助理与学科教学顾问，性格严谨、富有同理心且注重数据安全。你的职责是协助教师高效处理日常班务、排座调配、值日轮换、学情诊断与资料备课。
```

## 五、 系统日常运维与故障恢复规程

### 5.1 数据备份与灾难恢复规程
- **日常备份**：数据库位于 `%APPDATA%\class-manager\database.sqlite`。系统每次启动前会自动对现有数据进行快照归档；
- **冷备份迁移**：只需拷贝 `%APPDATA%\class-manager` 整个文件夹至新设备相同路径，启动客户端即可实现 100% 完整无损迁移；
- **回滚机制**：若教师误操作执行了批量修改，可通过 **【系统设置】 -> 【数据维护】 -> 【历史快照回退】**，一键选择历史时间点进行事务级回退。

### 5.2 大模型凭据安全轮换与失效处置
- 若发现大模型回复提示“鉴权失败”或“配额不足”：
  1. 登录对应模型平台（DeepSeek / 火山引擎 / Moonshot）检查账户余额与 Token 额度；
  2. 生成新 Key 后，在软件 **【模型设置】** 中更新保存；
  3. 点击 **【连通性测试】** 确认双通道绿灯即完成轮换。

### 5.3 常见排错速查表
- **现象：启动时白屏或加载缓慢**  
  *排查*：检查本地 SQLite 是否被其他进程独占锁定。关闭可能的残留后台进程后重新启动即可。
- **现象：打印座位表或值日表无响应**  
  *排查*：检查系统默认打印机服务（Print Spooler）是否正常开启，或在导出对话框中选择“保存为 PDF”进行离线查看。
