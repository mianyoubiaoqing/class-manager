## 2. 已确认的产品方向

| REQ-03 | 智能体在授权规则内自主执行；内部分析、材料及待办生成可自动处理。正式成绩、成长评价、学生通知和公开展示等正式变更或对外动作，须由教师审核确认。 |
| REQ-04 | 长期目标仍是可用于真实班级的试点版本；最新初版阶段先验证程序稳定性，不进入实际业务。模拟数据结果只作为软件测试证据，不能替代真实应用成效。 |

| REQ-06 | 当前尚未落实参与教师、真实数据或试用安排。 |

| REQ-11 | 初版“上课”已确认为教师主导的课堂辅助：备课材料全屏展示、教学环节切换、计时、提问提示及授课进度记录。不以无人自主授课为验收要求，虚拟教师、实时语音问答和学生端互动不默认纳入本次确认。 |
| REQ-12 | 初版面向 Windows 单机使用，不部署远程服务器、不提供多电脑共享数据或进度；保留 Linux 与 macOS 的兼容接口，将平台差异与业务逻辑隔离。跨平台安装包、系统集成和真机验证不是已完成或已承诺的初版能力。 |

| REQ-17 | 已确认采用当期临时分组、组间轮换：生成值日表时自动分组，在该计划覆盖周期内保持成员稳定，各组依次值日；教师可以调整当期名单，下一期可以重新分组，不维护长期固定小组。新计划或当期更正不能静默改写历史安排。 |
| REQ-18 | 成长档案已确认为教师本地使用：记录日常事件与谈话跟进、关联历次成绩，由 AI 起草阶段总结并经教师确认后入档。初版不增加学生或家长端，不把 AI 草稿自动写成正式记录。 |
| REQ-19 | 最新阶段目标为先保证程序稳定运行，暂不进入实际业务。按本轮交付讨论理解为使用合成数据验证已确认功能，不导入真实学生资料、不开展真实班级试用或对外业务动作；不是撤销八项软件功能。 |
| REQ-20 | 用户授权当前助手搭建 M0；后续功能由用户交给其指定的执行模型继续，再由当前助手审计。保留可重复检查、交接说明和明确基线，不自动发起其他模型任务或后台审计。 |

| 功能 | 当前状态 |

| 座位编排 | 基础范围已确认：布局、不可用座位、锁定位置及人工调整；剩余座位默认随机编排，见 REQ-16 |
| 学生成长档案 | 日常事件、谈话跟进、历次成绩关联及教师确认后入档的 AI 阶段总结已确认；教师本地查看，无学生或家长端，见 REQ-18 |
| 读书音量和噪音音量监测 | 按开发者决定仅预留接口；设备、标定和现场能力后续沟通，客户例外确认待完成 |

| 呼叫学生到办公室问问题 | 按开发者决定仅预留接口；渠道、送达及实际设备后续沟通，客户例外确认待完成 |
| 高考倒计时 | 初版须实际可用；采用可配置的目标日期建议 |
| 学科备课 | 教师输入课题并上传教材或参考资料，不内置教材库；须导出可编辑 DOCX 教案、PPTX 课件，首批学科、输入文件类型及模板仍待确定 |

## 5. 工程与交接验收建议（待确认）

- 分开维护面向申报的精简材料与面向开发维护的完整工程文档。

- 代码注释优先解释业务规则、设计理由、限制与异常处理，不逐行复述代码。公共接口说明输入输出、错误和副作用。

- 开发过程中保留有代表性的提示词、AI 输出、人工修改和验证记录；剔除密钥与学生可识别资料。
- 应用效果区分模拟验证、历史材料评估及真实试用；指标、基线和采集方法需先确认，结果按实际记录。
- 预算记录区分开发工具用量与应用调试调用；无法观测的部分明确标记，不声称已完成全项目硬性限额控制。

## 6. 下一步访谈

优先解决：

1. 评审 `README.md` 指向的工程默认值、全系统架构、稳定性规格和工单拆分；所有工单先为草案，不因创建文件自动成为已开工或已完成。
2. 用合成材料验证 DeepSeek 账号能力、普通题型和导出流程；密钥在实施阶段通过本地设置输入，本轮不访问或调用。
3. 初版先完成软件验证；真实试点、现场设备接入、客户隐私授权及申报材料的日期留待后续阶段确认。

随后解决：

- 教师与数据的获取责任、计划日期及可验证的本次交付范围。
- 维护窗口的起算事件和支持范围。
- 学科、年级、考试及班级关系；跨次考试比较的口径。
