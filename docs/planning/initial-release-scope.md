# 初版范围与最低工作流程候选

更新日期：2026-09-29。

状态：交付范围及提前期限已按最新访谈更新；已明确确认的内容单独标注，其余最低工作流程仍为设计建议。此文件不是已实现的功能清单。

## 1. 当前约束

- 最新阶段要求：先用合成数据验证程序稳定运行，暂不进入实际业务。八项软件功能与两项设备接口的范围保持，不以空壳替代功能；真实试点和申报材料不是当前稳定性验收门槛。
- 客户要求原始清单各项功能实际运行。开发者允许音量监测和呼叫学生两项只预留接口，实际接入初版后沟通；此例外的客户接受情况未确认。
- 初版在 2026-10-01 前交付，计划按北京时间最迟 2026-09-30 准备好交付包。此前 2026-10-05 的推算不再用于初版排期；七天维护窗口另行确定起算点。
- 一名开发者配合 AI，Windows 单机本地开发，最终用户疑似非开发者。仓库已进入 M0 实施，不能将底座完成理解为全功能按期承诺；桌面包不依赖 localhost 开发服务。
- 不再沿用“只实现成绩流程，其余仅规划”的建议；应通过确认每项最低可用深度控制工作量，而不是悄悄移除功能。
- 2026-09-29 已明确图像试卷输入：通过 OCR 转文本或富文本，或通过原生多模态模型阅卷。不得只交付纯文本评分入口，至少一条图像路径须实际可用；当前工程默认实装原生多模态，独立 OCR 保留接口，不要求同时实装两条路径。
- 同日明确初版不覆盖手写公式等复杂业务；设计默认聚焦客观题、文字或简单数值填空、有明确评分要点的短文本简答。图像输入要求保留，不以排除复杂业务退回纯手工转写。
- 同日已确认“上课”为教师主导的课堂辅助，包括材料全屏展示、教学环节切换、计时、提问提示和进度记录；不是无人自主授课。
- 同日已确认 Windows 单机部署，不提供远程服务器或多电脑共享；Linux 和 macOS 仅保留兼容接口与移植能力，初版验收平台为 Windows。
- 同日追加桌面封装要求：Tauri 或 Electron 二选一，当前建议 Electron；必须导出可编辑 Word 教案及 PPT 课件，默认 DOCX/PPTX。详见 `desktop-client-and-export.md`。
- 同日确认 DeepSeek 为初版服务商，开发者有 API Key。当前官方文档确认 `deepseek-flash` 支持图像，初版以其作为多模态设计默认，独立 OCR 保留接口；账号与样本测试未完成，详见 `deepseek-integration.md`。
- 同日确认备课资料由教师输入课题并上传教材或参考资料提供，初版不内置整套教材库。
- 同日确认座位基础功能采用布局、不可用座位、锁定位置与人工调整；自动编排默认只随机填充其余可用位置，不扩大到复杂优化规则。

## 2. 八项软件功能

每项都应能处理用户输入的合成测试材料并产生有意义的结果，保存后可重启继续使用。固定示例输出或无效按钮不计为实际运行；当前不导入真实学生资料。

| 功能 | 最低工作流程及确认状态 | 关键验收与未决事项 |
| --- | --- | --- |
| 座位编排 | 已确认布局、不可用座位、锁定位置及人工调整；默认先固定已锁定学生，再随机安排其余学生，方案可确认保存及打印 | 无重复学生或重复占位；座位不足、无效锁定或布局冲突明确提示。前排优先、避免相邻、成绩或身高规则和周期轮换暂不默认纳入初版。 |
| 学生成长档案 | 已确认教师记录日常事件与谈话跟进、关联历次成绩；AI 起草阶段总结，教师确认后入档，按学生时间线查看 | 初版仅教师本地使用，不增加学生或家长端；草稿与正式记录区分、更正可追溯，不把模型补充当作既成事实。 |
| 成绩分析 | 导入已有成绩或接收已复核阅卷结果，生成班级与个人分析、跟进草案 | 使用 `score-analysis-defaults.md` 的默认口径，保留来源与版本；模型失效不影响数值统计。 |
| 值日编排 | 已确认生成当期临时小组，成员在计划周期内保持稳定，各组依次轮换；教师可调整名单，下一期可重分组，计划保存并可打印 | 不维护跨计划的固定小组；新计划和当期更正不静默改写历史安排。检查人数不足、岗位缺口及人员不可用。 |
| 高考倒计时 | 设置名称、目标日期和时区，首页及课堂展示页显示剩余天数 | 重启保留设置，跨日刷新，到期显示明确状态；不固定考试年份或从网络猜测当地日期。 |
| 学科备课 | 已确认教师输入课题并上传教材或参考资料，初版不内置整套教材库；生成可修改的教案与课件，并导出可编辑 Word 和 PPT 文件 | 默认 DOCX/PPTX，文字及表格须为原生对象。内容引用已保存版本和所选资料；具体学科、输入文件类型、模板及实际办公软件待确认。 |
| 上课 | 已确认：教师打开备课材料，进行全屏展示、教学环节切换、计时、提问提示及进度记录 | 教师控制课堂过程；虚拟教师、无人自主授课、实时语音问答或学生端互动不作为本次确认的默认范围。 |
| 阅卷 | 接收图像试卷，采用 OCR 或原生多模态处理普通题型；结合确认的评分细则给出建议，教师对照原图复核并补评后进入成绩分析 | 至少一条图像路径须实际运行；手写公式等复杂业务暂不覆盖。不支持或识别不清的题目转人工，不能补零或漏题汇总。具体默认范围见 `paper-grading-design.md`。 |

共同基础为班级与学生名册、教师确认与操作记录、配置、数据存储及备份恢复。名册不只是某个页面的私有数据，各模块须使用可追溯的同一学生身份。

### 座位基础规则与验收建议

- 教室采用行列布局，过道或不能坐人的位置标为不可用；本次参与编排的学生来自已确认名册，不因导入顺序或缺少某项个人资料而遗漏学生。
- 锁定表示指定学生保留在指定可用位置；重新生成只重排未锁定学生。初版不需要采集视力、身高、性别或成绩来完成编排。
- 人工调整支持移动到空位和交换两个未锁定位置；调整锁定位置前须显式解锁，不因拖动或重新生成静默解除锁定。
- 容量不足、锁定到不可用座位或锁定关系冲突时，返回具体问题并保留已有方案；不生成重复占位的“成功”结果。布局变更影响已有安排时须重新校验，不能静默丢弃学生。
- 生成和调整先形成草稿，教师确认后生效并可保存、重开和打印；草稿未分配完时明确显示缺口，不标为完整已发布方案。
- 验收覆盖名册人数为零、可用座位恰好够用或不足、有空余座位、部分学生锁定、重新生成、人工交换及保存重开。确认方案中每名参与学生恰有一个可用座位，每个座位至多一名学生，锁定关系保持不变。

### 值日分组与验收建议

当期临时自动分组、周期内稳定、组间轮换、人工调整和下一期可重分组已确认。以下为据此采用的实现与验收默认值，尚未实现。

- 教师选择参与学生、当期值日日期与组数，默认尽量均分成员，每名参与学生恰属一个当期小组；组数不合法、人数不足或名单为空时提示问题，不产生空组冒充成功。
- 各组按确认的顺序在选定日期上依次轮换，不自行推断学校上课日或节假日。组内岗位和所需人数由教师配置；岗位分配不能让同一学生在同一时段重复占用岗位，人员不足显示缺口。
- 教师可调整当期名单或临时换人；临时替换只改变指定安排，不自动重排整期、不引入未经约定的跨期补班规则。
- 分组及轮换先形成草稿，教师确认后生效；保存当期成员和具体日期安排。下一期重新分组不改变上一期成员、值日表或已有记录，当期更正保留前一版本。
- 验收覆盖人数不能整除组数、日期少于或多于组数、名单调整、人员不可用、岗位缺口、保存重开及下一期重分组。按组顺序轮换可验证，但不宣称不同工作量岗位或不同人数小组已经达到个人劳动量公平。

### 成长档案规则与验收建议

日常事件、谈话跟进、历次成绩关联、AI 阶段总结与教师确认入档已经确认。以下为该范围内的设计默认值，不扩展到独立的家校沟通或综合素质评分系统。

- 日常事件与谈话跟进先采用文本记录，带发生日期、所属学生和记录来源；教师可补充行动及后续结果。录音、视频、自动谈话转写和任意附件管理不默认纳入本次确认。
- 历次成绩引用成绩模块已确认的记录和来源版本，不在档案中另建一套可以独立改分的成绩；成绩更正后能识别关联数据变化。
- 阶段总结基于教师选定时间段内的记录与已确认成绩起草，保留所用材料版本。无资料时明确说明不足，不编造事件、谈话或心理结论；不自动生成学生人格标签或德育分数。
- 教师可以编辑、确认或放弃总结草稿，确认后才成为正式档案记录；之后的更正保留修订信息。源材料变化不静默改写已入档总结，旧草稿需提示重新核实。
- 教师本地查看不意味着 AI 在本机推理。生成摘要若需调用 DeepSeek，仅发送允许处理且去标识化的必要事实；不得默认上传完整谈话记录。课堂展示、PPT 导出和诊断日志不自动带出档案私有内容。
- 验收覆盖建立事件、追加跟进、关联考试、无资料生成、编辑后确认入档、放弃草稿、成绩更正、应用重开和模型失败。模型不可用时仍可查看及维护本地记录，未确认草稿不能变成正式档案。

### 课堂辅助的验收建议

- 从一份已保存的备课材料进入课堂展示，教师能切换环节、查看提问提示和操作计时；退出全屏后仍能继续当前授课。
- 按班级和本次授课保存进度，再次打开能恢复记录；具体恢复交互在设计时确定，不将切换环节或计时结束当作学生已掌握知识的证据。
- 已保存材料的展示、环节切换、计时和记录不依赖当场调用模型；断网或模型失败不能阻断这些本地课堂操作。
- 学生个人成绩、成长档案、阅卷结果与教师私有备注不因进入课堂展示而自动公开；展示内容由教师确认。这是设计保护要求，不表示新增学生端。

## 3. 两项接口预留

“预留接口”要求可验证的 interface 与说明文档，但不要求本阶段采购硬件或完成真实接入。是否必须使用专用外设取决于将来选定的方案，不把“需要专用设备”当作已核实事实。

| 功能 | 初版建议交付 | 必须说明的限制 |
| --- | --- | --- |
| 读书音量和噪音音量监测 | 设备能力与连接状态、测量样本和异常的接口定义；未接入实现；使用合成样本验证的接口测试 | 不显示虚假的实时测量。量纲、校准、采样及数据保留尚未定；不得将未标定幅度直接声称为实际声压级，也不得仅凭音量断言声音来源或课堂纪律。 |
| 呼叫学生到办公室问问题 | 教师确认后的呼叫请求、发送状态与失败结果的接口定义；未接入实现与接口测试 | 未接入时明确不能送达，不将请求建立、模拟发送或设备接收等同于学生已收到；呼叫渠道和真实回执语义后续确定。 |

测试用模拟实现只在测试或明确标识的演示环境使用，不作为现场能力验收证据。接口字段和错误语义将在架构阶段确定，不提前绑定某厂商 SDK。

## 4. 工程方向与交付检查

- 架构候选为模块化单体：按业务职责分模块，共用身份和本地数据管理；小 interface 后封装计算、规则与错误处理。暂不为尚不存在的变化设计通用插件框架或微服务。
- 规则编排、统计与客观题评分由可测试程序完成；模型用于内容生成、解释及辅助判分。授权范围与教师确认逻辑由应用执行，不只依靠提示词约束。
- 模型和设备通过明确 interface 接入。设备预留是用户明确的后续扩展需求，应单独隔离；具体技术栈及调用框架尚未确定。
- 初版只规划一个真实 DeepSeek Adapter，密钥经受控应用进程配置和保存。模型能力按具体型号判断，不将服务商名称等同于所有模型均可看图；文档能力与真实验证状态分别记录。
- 阅卷将材料准备、可选 OCR 识别、辅助评分和复核发布分开，供文字与多模态路径共享数据版本和审核行为。两条路径及局部 UML 草案见 `paper-grading-design.md`，并非已经验证的模型实现。
- 涉及学生作答、档案文本或教材的新模型输入类型，须明确最少必要字段与处理授权，不能把“允许脱敏成绩调用云模型”扩大为任意材料上传许可。
- 各模块至少验证一个正常流程、一个无效输入或失败流程、保存后重启恢复；模型相关流程另测超时、无效输出及人工复核。
- 初版工程交接建议包含可启动包、源码、配置说明、安装与用户手册、开发者交接说明、架构及 UML、规格与工单、测试结果和已知限制。上述资料的准确性以实际实现为准，不写不存在的启动命令或未完成的能力。
- 使用模拟材料进行软件功能测试，不等于真实班级试点；教师及真实数据尚未落实，应用效果证据不能编造。
- 申报报告、视频及真实试用证据移至后续阶段，当前先保证软件稳定；保留后续需求，不把未开展的真实应用成效写成已验证。

### Windows 单机与跨平台准备

Windows 单机、不部署远程服务器、不做多电脑共享、Tauri 或 Electron 桌面封装，以及 Linux/macOS 接口预留均为已确认要求。下列技术选择为配合这些要求的架构建议，尚未实现或通过目标机器验证。

- 交互形态已改为桌面客户端，不再采用外部浏览器作为初版入口。建议 Electron + React + TypeScript，以模块化单体组织业务；数据库候选为 SQLite，附件存本地目录。非技术用户不需要单独维护数据库服务器，也不把 Docker、WSL 或开发命令作为启动前提。
- 打包版本建议加载内置界面资源，经有限的桌面桥接接口调用应用模块，不需要运行 HTTP 服务；开发阶段的 localhost 仅供开发调试使用。严格校验桌面调用来源、权限及参数，不把本地窗口视为可信执行任意系统操作的授权。
- 学生、考试、档案、材料和授课进度以本地数据为准。云模型仅处理经过授权的输入，不承载状态同步；已有本地记录和课堂材料的使用不依赖云模型在线。
- 程序目录与用户数据目录分离，应用更新不覆盖数据。业务记录引用材料标识或相对路径，不写死盘符、用户目录、路径分隔符或某台电脑的安装位置。

| 平台相关职责 | 兼容接口或实现约束 |
| --- | --- |
| 用户数据、配置、缓存与日志目录 | 集中解析平台标准目录，业务模块不自行拼接 Windows 路径；优先复用跨平台库 |
| 模型凭据保存 | 隔离系统凭据存储能力；Windows 初版接入选定实现，其他平台待适配。系统存储不可用时明确提示，不静默降级为明文文件 |
| 保存文件、打开目录及系统交互 | 使用框架提供的有限能力和小范围平台 Adapter，校验受控参数；业务模块不直接执行 PowerShell、批处理或系统命令 |
| 启动、打包与退出 | 平台差异留在桌面壳及构建入口；重复启动、未完成任务与正常退出有明确行为，不终止无关进程；打包运行不依赖开发服务器 |
| PDF、图像与后续 OCR 依赖 | 选型时检查各平台支持和分发条件；不能以接口存在为由声称原生依赖已经跨平台可用 |

- 避免把所有能力塞进一个通用平台接口，只为确有系统差异的操作提供接口；业务规则、评分、编排和统计使用同一套实现。
- 备份建议包含一致版本的数据库、必要附件与版本清单，恢复前保护现有数据。系统绑定的凭据不作为跨平台可移植备份，换机后由用户重新配置。备份恢复不等于多电脑实时共享或自动合并。
- Windows 验收覆盖普通用户权限、中文及空格路径、无开发环境下启动、重新打开后的数据保留、重复启动处理、可编辑文件导出与备份恢复。核心逻辑测试不得依赖固定 Windows 路径；Linux/macOS 的安装、权限、凭据、原生依赖及恢复演练列入后续验证，未运行则明确标记未验证。

### 可编辑教案与课件

- Word、PPTX 与课堂展示使用同版结构化教学内容，教师修订后保存再导出；点击导出不另行调用模型重写内容。
- DOCX 使用原生段落和表格，PPTX 使用原生文字与幻灯片对象；图片可保留为图片，但整页截图不能充当可编辑教案或课件。
- 默认不提供 Office 级任意版式编辑、任意 PPTX 导入或外部修改自动回写；这些不由“导出可编辑文件”推导出来。
- 导出候选库、职责、失败处理、视觉与实际编辑验收见 `desktop-client-and-export.md`。产品生成文件不依赖用户已安装 Office，但打开和编辑输出需要兼容办公软件。
