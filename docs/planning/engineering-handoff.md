# 开发规范与交接手册草案

日期：2026-09-29。状态：完整产品的开发与交接标准。M0 已实施，实际入口及步骤见[用户手册](../handoff/user-manual.md)和[开发者交接](../handoff/developer.md)；本文其余目标不表示对应业务已经实现。

## 1. 维护责任

开发者负责首次部署及约定的 7 天维护。起算事件、准确截止时刻、响应方式和问题范围仍待双方确认，不把“7 天维护”自动解释为 7 天开发或长期运维。

最终用户的自主维护限于正常使用、允许的配置、数据备份恢复、账号更换和诊断导出。依赖更新、程序缺陷、数据库升级故障及平台移植需要技术人员；不能通过交付源码要求非开发者承担这些工作。

交接表须写明：接收人、电脑系统与架构、安装版本、数据位置、备份位置、模型账号与费用归属、支持起止日期、已知缺陷、未接入设备、待验证能力。当前这些信息没有全部落实，保留待填而不代签。

## 2. 代码与注释标准

- 使用严格 TypeScript；跨 IPC、导入文件、数据库旧版本及模型输出都做运行时校验，不能用类型断言跳过校验。
- 按业务模块组织规则，调用方只依赖模块接口；模型 SDK、Electron、SQLite 和 Office 库放在对应实现中，不泄漏到每个页面。
- 统计、座位、轮换等规则尽量为确定性函数；时钟和随机源可注入。持久化、付费调用等副作用通过有限操作完成。
- 不使用无约束通用 CRUD、任意 SQL/命令工具或巨大“万能服务”代替业务操作。新增抽象须说明其真实变化点与测试收益。
- 公共接口注释写输入约束、输出、失败类别、取消、副作用、重试与幂等语义；复杂内部注释解释“为何如此”，不逐行翻译代码。
- 关键规则使用清楚中文说明，例如“缺考不是零分”“确认后冻结版本”“该重试可能再次计费”；变量、类型和文件名使用一致英文词汇。
- 注释与实现同时修改，不保留已失效的兼容说明；TODO 要关联工单、说明限制，不能成为未完成验收的替代品。
- 不硬编码开发者路径、API Key、学校或考试日期；配置区分用户设置与程序能力约束，超限不可被普通 UI 参数绕过。
- 锁定依赖及运行环境版本，记录许可证、原生依赖与分发要求。不是所有报错都用 `catch` 后返回空数组或成功。
- 日志记录操作 ID、版本、错误类别及必要耗时；默认不写姓名、答卷、谈话、密钥、请求体或完整模型输出。

注释示例的意图：说明“为何对未完成题目拒绝总分发布”，而不是说明“这里遍历题目”。这条规则必须同时有测试；注释不能代替实际检查。

## 3. 测试与完成定义

规则测试覆盖成绩状态、排名与总分口径、轮换、锁定、跨日、版本及完整性。应用接口测试覆盖确认、事务回滚、幂等、过期结果、迁移和备份。桌面 E2E 通过实际 UI 检查关键流程；打包测试覆盖开发模式无法发现的资源路径和原生依赖。

测试规模随风险扩大，不把行覆盖率 100% 当作唯一目标。对数据写入、密钥、入分和恢复必须测试失败路径。断网、超时、无效返回、磁盘/文件占用、重启中断都使用可复现条件，避免以真实数据试错。

每张工单完成时应有：可演示流程、对应自动测试、适用的打包检查、中文错误提示、文档更新和未解决限制。只完成界面、只通过 mock 测试或只有代码生成不算端到端完成。完整发布门槛见[稳定性规格](stability-spec.md)。

## 4. 面向最终用户的操作手册内容

实施时把下表扩展为实际步骤与截图；未实现的项目明确标注不可用。

| 任务 | 手册必须说明 | 验证标准 |
| --- | --- | --- |
| 安装与首次启动 | 支持系统、安装包来源与版本、普通权限、数据不存安装目录 | 无开发工具的 Windows 机器能按步骤启动 |
| 设置模型 | 账号归属、Key 本地输入/删除、独立文本及图像检查、可能费用 | 不通过聊天/截图交接完整密钥；失败时本地功能仍可用 |
| 识别当前阶段 | 当前仅合成验证、真实业务未启用、设备未接入 | 不把测试替身或虚构数据看成现场结果 |
| 导入与确认 | 模板、预览、身份匹配、重复/错误行、确认前可取消 | 未确认不改正式数据；拒绝原因可以定位到行或页 |
| 教师复核 | 草稿与正式记录区别、缺题人工处理、修订后重新确认 | 不会因模型返回就自动入分或入档 |
| 导出与课堂 | DOCX/PPTX 保存、办公软件要求、编辑不自动同步、展示范围 | 修改导出文件不改源记录，投屏不含私有备注 |
| 备份 | 包含哪些数据、不含 Key、保存位置与副本保护、备份验证 | 能恢复才算有效备份，不只检查文件存在 |
| 恢复 | 检查备份、保留当前副本、恢复会替换什么、失败如何保留旧数据 | 在合成环境独立完成恢复，不手工修改数据库 |
| 升级与卸载 | 先备份、兼容版本、升级失败处理、卸载是否保留数据 | 不默认删除用户数据，也不让旧版强开新库 |
| 求助与诊断 | 时间、版本、错误编号、复现步骤、脱敏诊断导出 | 不要求用户打开发者终端，不泄露学生资料或 Key |

日常建议：重要导入或确认前后建立已验证备份；修改账号时先确认余额与所有权；遇到数据异常先停止继续批量操作，保留诊断信息和完整数据副本，不反复重装覆盖。备份频率及保存介质在首次部署时结合使用频度明确。

### 常见故障处理边界

| 现象 | 用户可自行做 | 需要技术处理的情况 |
| --- | --- | --- |
| 模型认证/余额失败 | 检查所选账号、替换 Key、核对余额 | 正确配置仍持续异常或接口能力改变 |
| 网络超时 | 保留草稿、检查网络、确认费用风险后重试 | 持续失败、任务状态无法恢复 |
| 导出被占用 | 关闭目标文件或另存新位置 | 文件损坏、文字丢失、稳定复现的版式错误 |
| 备份验证失败 | 保留原数据与错误报告，改用已验证备份 | 所有备份不可用或发生数据库损坏 |
| 启动或迁移失败 | 保留错误编号和数据目录，停止反复安装 | 需要恢复兼容版本或修复程序 |
| 设备显示未接入 | 了解初版仅提供接口，不尝试发送实际通知 | 后续设备采购、协议适配与现场校准 |

## 5. 面向开发者的交接内容

M0 的实际目录、入口和脚本见 `../handoff/developer.md` 与根目录 `package.json`；后续模块继续补齐对应步骤，只记录真正执行过的检查。

1. 环境与构建：锁定 Node/包管理器/Electron 版本、安装依赖、开发入口、检查、构建、Windows 打包、签名与发布步骤。
2. 架构与数据：模块职责、依赖方向、IPC 白名单、数据目录结构、schema/迁移、材料与数据库一致性、任务恢复状态。
3. 扩展入口：新增模型 Adapter、OCR、设备 Adapter、教学模板及平台适配的具体接口和契约测试；未实现接口标注清楚。
4. 测试：固定随机种子和时钟、合成样本来源、单元/接口/E2E/打包命令、真实模型可选检查及费用提示。
5. 故障诊断：操作 ID 如何串联任务与发布，如何复现中断、排查过期版本、验证备份与迁移，不记录敏感原始 payload。
6. 发布与回退：版本号、变更记录、锁文件、依赖许可、安装产物校验值、支持系统、数据库兼容性、已知限制。
7. 交接风险：维护窗口、未验证 Office 软件、客户设备接口未获确认、云服务账号及费用归属、真实数据启用审批。

架构和 UML 用词以根目录词汇表为准；模块内 README 只解释定位入口及重要约束，不复制整份总文档。重要设计改变记录原因和替代方案，禁止仅修改图而不同步实现或反过来。

## 6. 发布证据模板

每条记录包含：验收项、工单号、构建版本、执行日期、系统/设备、合成数据版本、真实接口或测试替身、步骤、预期、实际、证据文件、结果、已知限制。结果仅可为“未执行 / 通过 / 失败 / 受阻”，没有执行结果时不能写通过。

M0 的执行结果见[验证记录](../handoff/m0-verification.md)。M1 和真实业务验收尚未完成，规划图示或 M0 核心测试不作为业务效果结论。

正式交接仍需接收人照手册完成启动、导入、备份恢复及一次错误定位。接收人未落实时记待验收；开发者演示不能代替用户独立操作的证据。
