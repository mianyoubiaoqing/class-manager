# 桌面客户端与可编辑教学文件导出

更新日期：2026-09-29。

状态：已确认桌面封装与可编辑 Word/PPT 导出；用户随后授权 M0 按 Electron 方案实施。M0 客户端现状见 `../handoff/m0-verification.md`，教学文档生成与导出仍未实现。下文保持完整产品设计及未完成的专项验收要求。

## 1. 桌面框架比较与建议

| 方面 | Electron | Tauri |
| --- | --- | --- |
| 执行模型 | Chromium 多进程模型，主进程可使用 Node.js；网页界面通过有限的桥接接口调用本机功能。[S1] | 使用平台 WebView，Windows 使用 WebView2；开发依赖 Rust 与相应系统工具，Windows 文档列出 C++ Build Tools。[S3] |
| Word/PPTX 导出 | 可在 Node.js 工作进程使用 JS/TS 文档库，并在本机保存文件。[S4、S5] | 同样可以使用支持浏览器的 JS 文档库，不存在“不能导出 Office 文件”的限制；另需规划保存接口和重任务执行位置。[S4、S5] |
| 当前项目取舍 | 便于将界面、业务及导出统一在 TypeScript 工具链中，是本项目的初版建议 | 当安装体积与运行资源成为明确约束时仍值得评估；目前需额外验证系统 WebView、构建及插件依赖 |
| 成本与风险 | 通常需要承担较大的分发包和运行资源开销，并维护 Electron 安全更新；本项目未做体积或性能实测 | 不能把使用系统 WebView直接等同于已经在三种系统稳定运行；实际体积、内存与兼容性也须实测 |

目前开发机 PATH 上存在 Node.js、npm、Rust 和 Cargo，因此推荐 Electron 不是因为 Rust 缺失；未验证这些工具的目标版本、完整 C++ 工具链或任一种框架的构建结果。单个开发机的工具情况也不能代表客户电脑。

建议初版使用 Electron、React、TypeScript 和本地 SQLite，不同时维护两套桌面壳。Tauri 是备选，不是本次必须实现的第二个客户端；Linux/macOS 的兼容要求通过业务隔离和平台 Adapter 保留，不承诺无需适配即可切换框架。

## 2. 客户端职责划分

- 安装后由桌面图标打开客户端，不以外部浏览器加开发服务器作为交付形态。开发阶段仍可使用 localhost 热更新；打包版本加载随包资源，默认不启动 HTTP 服务或监听局域网端口。
- Renderer 负责界面与交互，Preload 仅暴露经过类型和运行时校验的业务操作。主进程负责窗口、系统对话框和应用生命周期，将业务请求交给应用模块；不能把全部业务实现堆到主进程文件中。
- 云模型调用、密钥读取、数据库写入和导出保存位于受控应用侧；Renderer 不直接获得密钥、通用文件读写、任意命令执行或完整 IPC 对象。
- 初版服务商已指定 DeepSeek，模型能力、凭据设置、错误处理与验证要求见 `deepseek-integration.md`。用户输入密钥的表单仅短暂接收，提交后清空；已保存的完整密钥不回传 Renderer，不随安装包分发。
- 使用 `contextIsolation: true`、`nodeIntegration: false`、渲染沙箱、受限 CSP，并校验每个 IPC 调用的来源、操作及参数。加载的教材、OCR 文字、富文本和模型输出都按不可信数据处理，不允许执行脚本。[S2]
- PDF 处理、文档排版和批量识别使用可取消的工作任务，避免阻塞主进程或课堂界面。数据库写入由应用持久化模块协调，不能让多个导出工作进程自行写数据库。
- 本地数据目录、凭据保存、保存对话框、打开导出文件、窗口与生命周期各自保留有限接口；优先使用跨平台框架已有能力，不建立无边界的系统工具接口。
- Windows 包包含所需应用运行时，普通用户无需另装 Node.js、Rust、Python 或 Office 来生成文件。SQLite、PDF 或 OCR 若依赖原生二进制，须在打包前核实目标架构与分发许可，不能只验证开发模式。
- 初版建议手动安装与升级，不引入自动更新服务器；手册明确备份、迁移、回退及后续安全更新责任。安装包签名与客户机器策略需交付前核实，不以关闭系统安全防护作为安装步骤。

## 3. 可编辑的定义与导出流程

“Word”按 `.docx`、“PPT”按 `.pptx` 作为初版格式默认值；旧二进制 `.doc`、`.ppt` 不自动纳入要求。

| 产物 | 初版验收要求 |
| --- | --- |
| Word 教案 | 标题、正文、列表和教学环节表格使用原生可编辑内容；教师能修改文字、增删行并保存，不使用整页图片替代正文 |
| PPTX 课件 | 标题、正文、列表、例题和教学表格为可编辑幻灯片对象；实际包含的数据图表也须保留可编辑图表及数据，不用整页截图冒充课件 |
| 图片素材 | 照片、插图可作为图片对象移动、更换和缩放；不承诺自动把图片内文字变成可编辑对象 |
| 课堂展示 | 使用已保存的同版教学内容；原生课件编辑器、任意 PPTX 导入及 Office 级排版编辑不属于默认范围 |

已确认资料来源：教师输入课题并上传教材或参考资料，初版不内置整套教材库。推荐流程为教师补充学科、年级与课时，选择本次使用的资料及范围，生成结构化备课草稿；教师编辑并保存备课版本，再生成并保存对应的逐页课件内容。Word 导出读取教案结构，PPTX 导出与课堂视图读取课件结构；两者记录所用备课版本，不在点击导出时重新调用模型改写内容。

### 上传资料的设计要求

- 资料与备课版本建立来源关联，保留文件版本和可定位的页码或片段引用；不要求初版建立全量教材知识库或自动抓取教材网站。
- 上传后让教师确认选定的资料与可读内容，再用于生成。解析失败、内容不完整或超出处理范围时明确提示，不静默截断却声称已依据全书备课；具体文件格式和大小限制仍待设计确认。
- 引用资料的内容与模型补充建议分开标记，来源指向实际上传片段；无法核实的教材页码、课标出处或原文不编造。
- 上传到本地不等于已获准外发全部文件。只发送本次生成必要且获准处理的资料；其中的命令、链接或提示文字不能修改系统权限与已确认的教学要求。

### 模板与文件保存

教学目标、重点难点、教学环节、例题与练习是建议的教案模板内容。课件按讲授顺序组织。默认一套清晰的中文教案模板与 16:9 课件模板；学校模板、品牌及指定教材样式尚未获得，不承诺自动匹配任意模板。

模板排版由可测试的程序完成，模型只产生受限结构的教学内容。中文字体与回退规则须验证；长文字拆段或分页，不能为塞入一页无限缩小字体。题解、参考答案和教师私有提示按明确的展示选择处理，不能默认混入学生可见页面或泄露学生个人资料。

导出 Module 的调用方只需提供已保存的内容版本、格式及模板配置，获得文件或明确错误。候选公开库为 `docx` 和 `PptxGenJS`，依赖版本、许可及打包兼容需验证。[S4、S5] 产品生成文件不依赖 Microsoft Office COM、用户桌面自动化或本对话专用的文档工具运行时；阅读和编辑文件仍需用户有兼容的办公软件。

教师通过系统保存对话框选择路径。取消不是导出失败；文件被占用、权限不足或生成失败须保留原文件并给出可操作错误，避免留下伪装成功的半成品。覆盖已有文件必须确认，成功后可由用户明确操作打开导出文件。

同一版本可再次导出，失败重试不改动内容。默认不将用户在 Word/PowerPoint 中的外部修改自动回写到应用，也不把某份导出文件的存在当作应用源数据；如需往返编辑，另行定义版本与冲突规则。

## 4. 验证与交接

- Windows 打包冒烟：在没有开发环境的目标条件下安装、启动、建立数据、调用允许的模型、导出两种格式、退出重开和备份恢复；记录原生依赖、目标系统版本及架构。
- 文件结构检查：确认输出为有效 DOCX/PPTX，文字、段落、表格或幻灯片对象确实存在；排除“只有一张整页图片”的伪可编辑结果。
- 视觉检查：生成中文长标题、长段落、多页表格、多张课件等样本，逐页渲染检查溢出、重叠、缺字、分页及顺序。结构检查不能代替视觉检查。
- 实际编辑检查：在 Word、PowerPoint 中分别修改文字和表格或幻灯片对象，保存后重新打开。WPS 若是客户实际使用的软件，须补充相应编辑与渲染验证，不仅凭库的兼容性描述宣称通过。
- 一致性检查：使用教师修订后的版本导出，确认与课堂展示的内容版本对应；未导出的新修改不悄悄替换已导出文件，外部编辑不覆盖应用记录。
- 资料依据检查：验证上传成功、解析失败、选择部分页码、替换资料版本与超出处理范围的情形；生成结果不引用未提供的内容，也不把模型补充描述为教材原文。
- 故障与安全：验证保存取消、文件锁定、无写权限、导出工作任务失败、应用退出及重试；拒绝未授权 IPC、任意路径读取和模型输出中的脚本。
- 交接手册记录文件保存方式、需要的办公软件、字体限制、外部编辑不自动同步、安装升级与备份步骤。课堂展示可用不等于应用支持编辑任意 Office 文件。

Office 导出与完整业务测试尚未执行；M0 的 Windows 打包和名册/恢复检查另见 `../handoff/m0-verification.md`。所有初版功能仍受 2026-10-01 前交付及单人开发约束，M0 不能代表全功能已具备交付条件。
