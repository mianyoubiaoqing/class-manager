# 全系统架构草案

日期：2026-09-29。状态：完整产品架构草案；M0 已按用户授权落地名册与维护部分。具体代码组织、实现取舍及剩余限制见[开发者交接](../handoff/developer.md)。

## 1. 关键取舍

| 决策 | 工程默认与理由 | 边界 |
| --- | --- | --- |
| 桌面技术 | Electron + React + 严格 TypeScript，统一界面、本机流程和导出工具链 | 用户确认桌面封装，Electron 是推荐默认，不同时实现 Tauri |
| 组织方式 | 模块化单体，以少量业务操作封装完整规则 | 不引入微服务、消息队列服务器、通用插件市场或多智能体调度平台 |
| 本地数据 | SQLite 存结构化记录，应用数据目录存不可变材料 | 不把安装目录、当前工作目录或导出文件作为业务库 |
| 模型 | 单一 DeepSeek Adapter，集中配置模型能力 | 原生多模态为初版路径；独立 OCR 可替换接口先保留，不宣称双路径均可用 |
| 业务控制 | 程序执行确定性规则，模型提供受校验草稿，教师确认正式变更 | 模型不能直接执行 SQL、任意工具、系统命令或学生通知 |
| 跨平台 | 隔离文件选择、凭据、路径、窗口和打印等平台操作 | Windows 是唯一初版验收平台，Linux/macOS 未实装与未测试须明确 |

Electron 进程和安全依据见[桌面专题](desktop-client-and-export.md)，模型能力依据见[DeepSeek 专题](deepseek-integration.md)。依赖版本在实施时核对、锁定并记录，不以本文替代安装与打包验证。

## 2. 运行结构

```text
本地管理界面 / 只读课堂展示界面
                |
       具名、限权的 Preload 操作
                |
       IPC 来源检查与运行时校验
                |
   应用用例：执行规则、审核、事务、任务
       |              |              |
   业务模块       模型与材料任务     平台操作
       |              |              |
 SQLite + 附件   DeepSeek / 工作进程  凭据 / 对话框
```

Renderer 只持有界面状态和受限数据；Preload 不暴露通用 IPC、文件路径读取器或任意调用函数。Main 负责生命周期、窗口和调度，不承担整套业务实现。PDF 栅格化、解析、导出等重任务放入工作进程；数据库由单一写入协调者管理，工作进程返回结果而不各自写库。

打包版加载内置资源，推荐受限自定义协议，不依赖 localhost 开发服务器，不监听外部端口。开发环境热更新仅是开发入口。课堂窗口仅接收已批准的展示内容，不能复用管理界面全部数据或桥接权限。

界面启用上下文隔离、沙箱、禁用 Node 集成与受限 CSP；校验 IPC 来源与参数，禁止任意跳转和自动打开模型返回链接。这些措施依据 Electron 官方安全建议，仍须通过项目测试验证，不能仅靠配置名宣称安全。[S1]

## 3. 模块与小接口

下列操作是语义约定，不要求机械地逐个创建同名类。调用方提交业务意图；校验、版本、事务和恢复规则由负责的模块统一处理。

| 模块 | 对外主要操作 | 内部负责 | 不负责 |
| --- | --- | --- | --- |
| 名册 | 建班、维护学生、查看成员 | 稳定学生标识、班级归属期间、停用 | 用姓名推断身份 |
| 成绩 | 预览导入、确认导入、查看统计、发布复核结果 | 状态与分值校验、成绩版本、确定性指标、重复发布保护 | 让模型计算排名或擅自赋分 |
| 座位 | 生成草案、调整、确认、打印 | 布局版本、锁定、冲突、学生覆盖 | 推断身高、关系或能力 |
| 值日 | 按期生成、调整、确认、查看日程 | 当期分组、轮换、岗位、历史版本 | 维护永久小组 |
| 成长档案 | 记录事件、关联成绩、起草及确认总结 | 事实来源、跟进状态、总结版本 | 心理诊断、家长端发布 |
| 教学材料 | 导入材料、选择范围、保存识别修订 | 原文件、页序、引用、有限格式、处理状态 | 任意文件执行或整套教材抓取 |
| 备课 | 起草、编辑、保存备课版本 | 教案与课件结构、引用、教师私有内容 | 自动回收 Office 外部修改 |
| 导出 | 从指定版本生成 DOCX/PPTX、保存 | 模板、分页、原生对象、原文件保护 | 点击导出时重新生成内容 |
| 课堂 | 启动展示、切换环节、计时、保存进度 | 指定备课版本、投屏过滤、离线恢复 | 自主授课或学生资料投屏 |
| 倒计时 | 设置目标、读取剩余时间 | 时区、跨日、到期规则 | 推断某年各省考试安排 |
| 阅卷 | 绑定答卷、设置细则、生成建议、复核、申请入分 | 页序、题目覆盖、人工补评、依据与修订 | 把无法判断记零或绕过成绩模块写库 |
| 外设 | 查询状态、请求监测、请求呼叫 | 契约、未接入错误、测试替身 | 伪装现场采集或送达 |
| 维护 | 备份、验证恢复、导出诊断 | 一致快照、迁移保护、日志脱敏 | 自动修复未知数据损坏 |

应用模块通过注入的模型、存储、时钟、随机源和平台 Adapter 测试。只为真实变化点提供接口，不为每个实体建立无意义的 Repository/Service 转发层。

## 4. 统一约束与版本

- 学生使用稳定内部 ID；班级成员关系有生效期间。重名不自动合并，学号冲突必须处理，改名和转班不能重写既往考试或计划。
- 已确认或被引用的版本不可原地覆盖。座位、值日、评分细则、成绩和备课修改形成新版本；草稿可编辑，确认时冻结确切内容。
- 金额无关，但成绩仍不能依赖浮点累加误差：科目声明允许的小数位，使用定点或十进制方式运算；统一舍入规则见成绩专题，禁止各页面自行实现。
- 更新请求携带预期版本。即使单机，多窗口、异步任务和重复点击也会造成陈旧写入；发现冲突须重载并提示，不静默覆盖。
- AI 解释、成长总结和导出产物记录所用来源版本。成绩或来源变更后旧结果标记过期；旧记录仍可追溯，重生成须显式触发。
- 布局及当期组成员是计划快照的一部分；本期调整产生修订，不修改已完成日期记录。缺少成员或布局容量不足时先报冲突，不私自删除学生。

## 5. 两条重要流程

### 阅卷确认入分

1. 导入并预览答卷，人工确定学生、考试科目、页序及评分细则版本。
2. 任务只处理已选范围，输出逐题建议；应用校验题号、分数范围、缺题和证据，不支持或看不清的题转待人工。
3. 教师对照材料修改并补评；只有题目齐全且分值合法时，才能确认该份建议的冻结版本。
4. 以复核记录 ID 作为幂等发布标识，成绩模块检查预期成绩版本；发现已有成绩时先展示替换差异并要求明确确认。
5. 单个数据库事务记录复核凭据、新成绩版本和操作记录；重复请求返回既有结果。任何一步失败均不得留下“审核成功但成绩重复/半写入”的状态。

这不是通用审批引擎。成绩、总结、计划各自保留必要的确认规则，仅复用版本检查与事务等基础能力。

### 备课、导出与课堂一致

选定资料版本 → 生成结构化草稿 → 教师编辑 → 保存备课版本 → 基于同版内容导出或展示。教案、课件是同一备课版本下不同视图，不是三次独立生成。课堂开始前确认展示范围；私有备注和未选答案不下发课堂窗口。外部编辑 DOCX/PPTX 不回写源数据。

## 6. 任务、外部失败与预算

长任务状态为 `queued / running / succeeded / failed / cancelled / interrupted`。任务记录输入版本、任务类型、模型/提示词配置、重试次数、错误分类及可观测 usage；不在普通日志中保存原始请求、图片、密钥或完整回答。

默认单个付费任务并发执行，后续按测量调整。超时、取消及应用退出后保留已确认数据。重启发现遗留 `running` 任务标为 `interrupted`，不得自动重放付费请求；用户重试生成新尝试，旧结果晚到也不能覆盖新版本。

认证、余额、无效参数、格式/业务校验失败不无限重试。限流和临时网络故障有限退避；失败原因必须可理解。取消不保证服务商停止计费，返回 usage 缺失记“未知”。应用账本只覆盖可观测应用调用，开发工具用量单独登记，不能据此声称已实现全项目 10 亿 token 硬上限。

## 7. 材料、备份与恢复

原始文件只读保存，解析稿、去标识化图像和修订分别存放；每份材料有类型、哈希、大小、页数及来源版本。Renderer 通过受限材料 ID 请求预览，不提交任意本地路径。资料正文、OCR、模型输出均是不可信数据，不改变授权或触发工具。

附件先写暂存文件、校验并完成持久化，再登记数据库引用。崩溃留下的孤立文件可在确认未被引用后清理；已提交记录必须有完整附件。删除、备份、恢复与写入共享协调规则，不在数据库事务中假设文件系统也能自动回滚。

备份流程暂停新写入和附件变更、等待活动提交，使用 SQLite 支持的一致快照方式及确定的附件清单生成备份，最后校验清单后恢复写入。SQLite 提供备份接口，但附件一致性需要本项目另行协调，不能复制正在使用的单个数据库文件就宣称完整。[S2]

恢复先解包到隔离暂存目录，校验格式版本、文件哈希、引用完整性、数量与展开大小；拒绝绝对路径、越界路径、符号链接等危险条目。保留当前数据快照后停写并切换，记录恢复阶段；启动时若发现中断则恢复完整旧版本或完成已校验新版本，不能使用半套目录。禁止在恢复验证前覆盖原库。普通业务备份不包含凭据；换机须重新配置 Key。

## 8. 维护和扩展界限

建议源代码按桌面入口、业务模块、外部 Adapter 三类组织；同一业务规则只在拥有它的模块实现。领域逻辑不得依赖 Electron 对象、Windows 路径或模型 SDK。数据库迁移明确升级顺序与兼容版本，迁移前备份，失败不继续写新库。

不承诺旧安装包可直接打开新数据库；回退是恢复兼容备份与对应程序版本。初版手动升级，没有自动更新服务器。安装签名、目标 Windows 版本、处理器架构和办公软件验证在发布前记录；不让用户关闭安全防护来完成安装。

日常维护应允许普通用户通过界面完成备份、恢复、配置和诊断。代码缺陷、依赖升级、平台迁移及服务商变更仍可能需要开发者；交接不能把非技术用户当作长期程序维护者。
