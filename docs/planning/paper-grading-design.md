# 试卷识别与辅助阅卷设计草案

更新日期：2026-09-29。

状态：用户已要求图像阅卷并排除初版的手写公式等复杂业务，初版服务商已确定为 DeepSeek。已核对官方文档，当前设计默认采用支持图像输入的 `deepseek-flash`，账号权限及效果尚未验证。以下流程、接口和局部 UML 尚未实现，不代表两条路径都须实装；普通题型范围仍采用设计默认值，学科、输入质量及验证样本待确定。

## 1. 输入与交付深度

- 初版须有实际的图像输入阅卷路径，不能仅作为未来接口预留。OCR 与原生多模态是可选技术路径，不因“或者”推导为必须同时实现两套。
- 建议先接受 JPG、PNG 与 PDF；PDF 在本地按页呈现，图像型页面进入所选路径。不依赖服务商一定支持原生 PDF，也不因 PDF 可提取文字就认定文字完整可靠。
- 明确三种材料角色：题目材料、标准答案及评分细则、学生答卷。上传空白试卷只能帮助建立题目材料，不能凭空生成学生成绩。
- 教师选择考试、科目和学生，确认答卷页序及所属关系。建议初版按单名学生的一份或多页答卷处理，允许人工调整页序与题目区域；全班混合扫描自动拆卷不是默认承诺。
- 用户已明确排除初版的手写公式等复杂阅卷。普通手写答案没有因此被一并排除；清晰的选项、数字和中英文短句作为候选输入，须经过样本验证，不承诺任意笔迹均可识别。
- 初版仍须在 2026-10-01 前交付。指定 DeepSeek 后，当前设计默认以 `deepseek-flash` 原生图像能力作为主路径，独立 OCR 保留接入位置；具体依据和账号验证要求见 `deepseek-integration.md`。不将不支持图像的 `deepseek-v4-pro` 作为自动替代，也不以官方支持替代实际阅卷效果验证。

### 普通题型默认范围

“排除复杂业务”已确认；下表是据此选择的设计默认值，不是客户对各题型逐项给出的验收要求。实际支持清单应在选定样本验证后写入用户手册。

| 范围 | 初版设计默认值 |
| --- | --- |
| 客观题 | 清晰印刷题干，单选、多选、判断；识别学生答案后按教师确认的答案和给分规则评分，不把所有多选题预设为同一种部分给分规则 |
| 填空 | 明确文字、词语或简单数值答案；按教师确认的可接受答案及单位等要求核对，不做公式等价证明或符号运算 |
| 简答 | 有明确评分要点的短文本回答，AI 提供建议及原图依据，教师复核 |
| 暂不自动处理 | 手写公式、数学推导、几何作图与图形推理；按本轮范围收敛建议一并暂缓复杂表格推理、复杂化学表达及长篇作文综合评分 |
| 无法识别 | 模糊、歧义、涂改或无法对应题目的内容，标记待人工处理，不猜测原意 |

支持由题型和作答内容决定，不只按学科名称决定。例如数学单选题可以属于支持范围，但需要读图推理的题目不会因为是单选就自动纳入。含不支持题目的混合试卷仍可保存、预览和处理其余题目；完整成绩发布前由教师依据评分细则补评分或处理未决问题，不能缩减试卷满分或悄悄跳过这些题目。

## 2. 主路径与保留路径

下表保留两种架构形态；当前 DeepSeek 初版默认采用右列多模态路径，左列为独立 OCR 的替换方案。图像账号权限或样本验证失败时须处理该问题，不静默降级成仅接收人工转写的文字，也不未经确认引入其他云服务商。

| 阶段 | OCR 加文本模型 | 原生多模态模型 |
| --- | --- | --- |
| 材料准备 | 本地校验、分页预览、页序与材料角色确认、去标识化 | 使用同一材料准备流程 |
| 理解输入 | OCR 生成有页码和来源区域的文字、段落及选项识别稿，其他内容保留原图引用 | 将经允许处理的页面或题目区域及评分细则交给支持图像的模型，按普通题型范围处理，不强制先完成整卷 OCR |
| 阅卷 | 已支持的客观题按规则评分；文本模型依据识别稿和评分细则生成主观题建议 | 从图像读取作答，生成逐题建议及来源依据；可明确识别的客观答案仍交给规则核对 |
| 信息不足 | 不支持的复杂内容或无法识别的作答保留原图并转人工处理，不编造内容补齐 | 看不清、超出支持题型、题号不确定或无法提供作答依据时转人工处理，不假造完整转写 |
| 共同输出 | 逐题评分建议、评分细则版本、作答依据及待处理问题 | 同左；可带识别片段，不伪称一定生成了完整识别稿 |

仅接收文本的模型不能理解一个本地图片路径。初版遇到评分所需的复杂图形信息时转人工处理，不因模型具备视觉能力就自动扩大题型范围，也不会静默上传给另一个服务商。

“富文本”初版建议保存为段落、列表、题号、选项和来源引用等结构化内容块，可向模型提供 Markdown；复杂公式和表格的结构化恢复不是本阶段验收要求。展示使用受限渲染，不执行上传材料或模型生成的 HTML、脚本和外链。识别稿是可编辑的衍生记录，不能覆盖原始答卷。

## 3. 复核与正式成绩

1. 建立或导入题目、每题满分、标准答案和评分细则，教师确认后形成版本。识别或生成的参考答案只能是草稿；缺少已确认的评分依据时不能作为正式判分依据。
2. 上传学生答卷，确认学生、考试、科目、页序与题目对应。保留本地原件和处理后页面的版本关系，坐标引用必须对应具体页面版本。
3. 在授权范围内运行所选路径，生成评分草案。每项建议带题目标识、建议分数或待处理状态、所用规则、简短可核对的评分依据及原图位置；不要求模型输出内部思维链。
4. 教师对照原图、识别结果和评分建议，纠正识别文字、题目对应和分数，并给不支持自动处理的题目人工评分。记录人工评分的来源与依据，不标为模型自动判分。识别与评分可以在同一复核界面处理，不要求正常页面多次确认。
5. 应用校验应评题目是否齐全、分数范围及步长是否有效、阻断问题是否已处理。只有教师确认的当前版本才能发布到成绩分析；未完成答卷显示不完整，不冒充考试总分。
6. 原图、题目对应、识别稿或评分细则改变后，相关评分建议与审核失效，须重新计算或人工复核。既往发布记录保留，更正生成新版本，并使下游分析识别旧版结果。

答题区域确认为空白并依据规则判零分，与照片模糊、缺页或无法识别不同；后者是“无法判定”，不自动计零分。模型自报置信度不等于经校准的准确率，缺少时显示未知，高置信度也不能绕过正式审核。

题目关联使用评分细则中的稳定标识；不同大题都显示“第 1 题”时不能混淆。答卷上已有批改痕迹或分数不是本轮评分标准；评估须标记此类样本，避免把读取旧分数误认为独立阅卷。

## 4. 模块与 Interface 候选

| Module | 对调用方的 Interface | 隐藏在 Implementation 内的复杂度 |
| --- | --- | --- |
| 试卷材料 | 将文件准备为可预览、可定位且有版本的材料，管理材料角色与本地保存 | 文件检测、PDF 分页、方向调整、裁剪与原图映射、去标识化衍生页 |
| 文档识别 | 将许可的页面读取为识别稿、来源位置与未决问题，不返回正式成绩 | OCR 或视觉转写 Adapter、普通版面及选项解析、供应商差异；复杂内容保留原图引用 |
| 辅助评分 | 依据题目、评分细则及文字或图像作答生成统一评分草案，不直接发布 | 客观题规则、文本或视觉评分 Adapter、结构化输出校验与调用失败 |
| 复核发布 | 接收教师修订及确认，校验当前版本后发布成绩或返回阻断原因 | 学生及题目关联、来源版本一致性、审核记录、幂等发布及更正通知 |

原生多模态路径可跳过文档识别 Module，但不能跳过材料准备、评分校验和复核发布。OCR Adapter 与视觉评分 Adapter 职责不同，不强行包装成丢失图片或来源信息的同一 `ocr()` 函数。

只在这些已明确的变化点设计 Interface，不建设任意节点编排平台。选用的真实 Adapter 须经过样本验证，未实现的 Adapter 明确不可用；测试替身不算真实接入。

### UML 与详细来源定位

原局部类图已整合到[全系统 UML 的评价与成长视图](uml.md)，图源统一维护于 [assessment.mmd](diagrams/assessment.mmd)，不再维护第二套独立的审核/成绩关系。

总览用 `SourceAsset` 简化表示原材料，实施仍须保留文档版本、页码、区域与变换映射；`QuestionAssessment.evidenceLocator` 指向确切材料版本的页和区域。可选 OCR 的识别稿是衍生记录，不覆盖原图，也不是多模态主路径必有对象。题目评估必须引用对应 `RubricVersion` 中稳定的 `QuestionRule.questionId`，不能只保存显示题号。

总览的 `GradingReview` 表示成功确认的冻结版本，而非所有编辑与否决操作；操作历史另行记录。`ScoreRevision` 是考试科目成绩快照，其中该学生的 `GradeEntry` 保存正式分数。图中的空结果表示可能在处理或失败，不表示允许发布空白成绩。完整性与当前版本检查仍由复核发布流程承担。

## 5. 安全、失败与成本

- 去标识化在首次外部调用前完成，包括云 OCR；不是先上传原卷再删返回文字中的姓名。原件保留本地，对外发送经检查的页面或必要区域，清除可识别文件名和元数据；姓名、学号、二维码及正文中的个人信息都需检查。
- 预览上的黑色覆盖层不构成可靠遮盖，应发送重新生成的实际遮盖图像；PDF 不发送仍含隐藏文字层或原始附件的版本。保留手写图像也不等于不可重新识别。
- 图片云处理许可及服务商保留政策待明确；此前用合成或有许可样本验证，不将“脱敏数据可调用云模型”解释为任意原卷可上传。
- 试卷、作答、识别文字及模型输出是业务数据。材料中出现“忽略评分标准”“运行命令”等文本，不得修改系统权限、调用工具、替换已确认规则或发布成绩。
- 校验实际文件类型，限制 PDF 页数、字节、像素及渲染资源；具体限额在目标设备和服务商能力核实后确定。拒绝无法安全处理的文件，不执行嵌入内容或访问材料中的外链。
- 按页或按题保存进度；超时、限流和无效输出有限重试或由教师重试，取消后不再启动新调用。中断恢复既有草稿，不重复发布或重复计入成绩。
- 应用检查返回分数、题号和来源引用。越界分数、未知题号、遗漏或非法定位进入待处理状态。缓存包含模型、图像、规则及输入版本，不能复用与人工修订冲突的旧结果。
- 记录可观测的 token、图像或页数计费和调用次数。云 OCR 可能按页计费，10 亿 token 上限不能替代货币费用控制。单次、单批预算及统计方式待确定，不声明已实现全项目硬限额。
- 交接文档覆盖更换模型、检查连接、处理识别失败、备份材料和更正成绩；日志不写密钥或原始学生作答，诊断导出遵守最小必要范围。

## 6. 验证与工单候选

先以有人工标准答案和评分标注的非敏感样本验证，再冻结服务商及路径。合成样本可证明流程，但不足以证明真实场景准确率。

| 测试场景 | 验收关注点 |
| --- | --- |
| 清晰客观题与人工金标准 | 在已支持答案形式内正确识别并按确认规则计分，总分可复算 |
| 清晰印刷题干加手写选项、数字或短句 | 使用人工转写及评分标准核验；识别歧义能进入复核并定位原图，不以支持图片格式代替准确率验证 |
| 手写公式、几何图、复杂表格或长篇作文 | 验证超出范围时保留原图并转人工，不生成看似成功的自动评分；教师补评后才能发布完整成绩 |
| 普通题与不支持题型混合 | 已处理题目的结果保留，未决题目不补零、不从总分和满分中删除，人工补评有记录 |
| 旋转、模糊、缺页、重复页与错序 | 预览可纠正；未解决问题阻断完整成绩发布，不自动当空白答卷 |
| 多页连续题与重复显示题号 | 题目标识对应正确，跨页来源不丢失，匹配不确定进入复核 |
| 修改识别稿、题目关联或评分细则 | 相关草案及审核失效，重新复核后才可发布；保留既往记录 |
| 无效输出、超时、限流或进程重启 | 保留进度和错误，不产生虚假分数或重复发布 |
| 含身份信息或提示注入的材料 | 外发载荷符合授权与遮盖要求，材料文字不触发系统操作 |
| 同一样本的两条路径比较 | 仅在两条真实路径均接入时对比识别错误、评分偏差、复核耗时及成本，不以自报置信度替代金标准 |

正式评审草案见[工单索引](tickets.md)中的 11、12、15：图像建议与复核、确认成绩入分、异常及交接验收。依赖包括 DeepSeek 配置、名册及考试成绩规则；当前仍为本地草案，尚未批准开工。

## 7. 未决事项

- 普通题型的首批学科与验证样本、图像质量及处理规模。手写公式等复杂业务已排除，不再作为初版必做能力反复询问；其他复杂内容采用上文暂缓默认值。
- 验证 DeepSeek Flash 多模态默认主路径；独立 OCR 保留替换接口，若主路径未达到题型验收标准再决定是否追加 OCR，不默认要求初版同时完成两条路径。
- 标准答案及评分细则由谁提供，可接受的识别错误、评分偏差与复核耗时。
- 图片和文本的实际云处理许可、DeepSeek 账号的图像权限及货币费用上限；已指定服务商不代表授权上传任意原始答卷。
- 目标系统已确认为 Windows 单机，保留 Linux/macOS 兼容接口；仍需核实目标电脑资源、PDF/OCR 原生依赖、处理限额及材料保留与删除规则。
