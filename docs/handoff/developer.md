# M0 开发者交接

日期：2026-09-29。以当前源码与锁文件为准，完整产品设计仍见规划目录。M0 已实现本机数据基础，后续业务尚未实施。

## 1. 入口与职责

| 位置 | 职责 |
| --- | --- |
| `src/shared/contracts.ts` | 对外数据类型、输入校验、有限桌面操作清单 |
| `src/main/main.ts` | 窗口、来源校验、IPC、原生文件对话框、导出与脱敏诊断 |
| `src/main/preload.ts` | 只暴露具名操作，不暴露 Node、任意 IPC 或文件能力 |
| `src/main/worker-client.ts` | 请求关联、工作线程退出与 30 秒超时保护 |
| `src/main/worker.ts` | 串行执行本机数据操作；校验输入，屏蔽底层错误 |
| `src/core/workspace.ts` | 名册、归属历史、版本检查、数据入口切换与恢复前副本 |
| `src/core/database.ts` | SQLite Schema 1、事务、版本及结构检查 |
| `src/core/snapshot.ts` | 统一读取与关系完整性检查 |
| `src/core/backup.ts` | 有界备份协议、哈希、附件一致性、暂存验证 |
| `src/core/files.ts` | 同目录临时文件、持久写入及发布 |
| `src/renderer` | 名册和维护界面，不执行数据库或系统命令 |
| `tests`、`scripts/desktop-smoke.mjs` | 核心与故障测试、真实 Electron 流程验证 |

平台差异留在 Main；核心规则只依赖 Node，不依赖 Electron 对象。M0 打包页使用本地 `file:` 资源，精确校验主窗口 URL 和主 Frame；这是当前实现，与规划中的自定义协议建议不同。新增页面或协议时必须同步审查来源白名单，不能简单放宽为任意 `file:`。

## 2. 数据与恢复协议

```text
用户数据目录/
  workspace-data/
    current.json
    workspaces/<UUID>/
      data.sqlite
      assets/<UUID>.bin
    staging/<UUID>/
```

`current.json` 指向当前完整数据库/附件集合，另记录最近一次恢复前集合。恢复先校验输入，再准备独立集合，最后通过同目录临时文件重命名发布入口。入口发布前退出时旧集合继续有效；发布后退出时新集合有效。恢复前数据不被物理覆盖。

学生 ID 独立于姓名与编号；转班/停用结束旧归属记录，恢复在籍创建新记录。编辑需实体 revision，所有写操作需数据集 epoch。恢复会换 epoch，旧窗口命令失效。时钟回拨时，归属时间不早于已记录时间。

附件先持久保存后登记引用；备份只收录数据库引用的附件，不复制整个用户目录。备份时 `VACUUM INTO` 创建一致数据库快照，工作线程串行执行保证同一时段无应用附件写入。持久化日志模式为 DELETE、同步 FULL。不存在跨进程多写入支持。

备份是严格结构的 JSON + Base64 内容，不是 ZIP。哈希用于损坏检测，不是身份认证或加密。导入前限制总体积，拒绝额外字段/路径、重复附件、未知 Schema、额外 SQL 触发器/视图、缺附件和错误哈希。恢复暂存与历史集合暂不自动清理。

目前没有旧版生产数据迁移，Schema 1 之外一律拒绝。新增 Schema 时须实现并测试升级/备份兼容策略，不能只改版本常量或结构白名单。`node:sqlite` 在开发用 Node 24 上仍有 ExperimentalWarning，因此锁定运行版本并保留 Electron 打包测试；升级运行时需重新验证。

## 3. 重复执行

实际脚本以 `package.json` 为准，先 `npm ci`，再 `npm run check`。检查包含格式、类型、Lint、核心测试和构建；格式修复为 `npm run format`。

`npm run test:desktop` 用 Playwright 的 Electron 接口启动真实窗口，在独立临时目录操作合成数据。原生文件选择/保存对话框由测试替换返回值，实际文件读写、校验、恢复和 SQLite 均真实运行；这不是人工对话框验收。测试包含截图、隔离验证、单实例、正常/失败/取消、回退和 10 次重开。

`npm run dist:win` 生成 NSIS 安装候选及 `release/win-unpacked`。随后执行 `node scripts/desktop-smoke.mjs --packaged` 验证打包程序。实际安装候选不能仅以开发模式测试替代。

`CLASS_MANAGER_DATA_DIR` 可覆盖 Electron 用户数据根目录，仅供开发、测试或明确部署配置使用。测试始终创建独立临时根；避免让自动测试使用用户默认数据目录。环境变量不包含 Key。

恢复中断测试在独立 Node 子进程的入口切换前后执行 `process.exit(77)`，验证再次打开时读取完整集合；它不等同于物理断电、磁盘损坏或操作系统崩溃测试。工作线程无响应测试检查超时后停止接受写入，而不是自动重试可能已提交的操作。

## 4. 后续扩展

新增业务优先复用名册身份、revision/epoch、事务和备份注册机制。新增 IPC 操作需在 contracts、Preload、Main/Worker 分发和测试中显式登记；Renderer 只能拿到该操作必要的数据。

当前备份会严格核对 SQL 结构，新增表后必须同时更新备份版本、迁移方案和往返测试。新增附件类型须保持不可变标识、尺寸和哈希校验，不能绕过附件清单另存一套不被备份的数据。

模型接入按工单 03 独立进行：凭据与日志隔离，失败不会破坏本地名册。M0 没有预埋 Key、共享服务账号或可用的模型 Adapter。后续业务功能及 M1 发布门槛见对应工单。

## 5. 构建与限制

当前没有自动更新服务器或代码签名证书，安装器采用按用户安装配置并默认保留数据。代码签名日志不能代替证书验证；交付须明确未配置签名和目标机待验收状态。

打包不需要 SQLite 原生扩展重编译，使用 Electron 内置 Node 的 SQLite。前端库打包可能报告 `use client` 指令警告；本应用不采用 React Server Components，该警告当前非失败项，仍须保留实际构建日志。运行依赖审计结果只代表查询当日已知通告，不是没有安全风险的保证。

后续需要补充目标机普通权限安装/卸载、干净系统、长期运行、磁盘空间/权限/占用等实机场景；不要用 mock 或当前开发机测试替代。Linux/macOS、真实班级数据及 M1 功能均未验收。
