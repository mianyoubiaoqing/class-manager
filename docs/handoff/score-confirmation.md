# 成绩确认与历史交接

更新：2026-09-30。本文记录工单 04 第四阶段后台接口。后续已接入 [桌面接口](score-desktop.md) 和 [教师页面](score-ui.md)，04 的最终技术验收已通过。下文保留阶段设计及当时验证，不将旧测试时间用作最新发布证据。

## 接口与状态

`Workspace.scores` 持有 `ScoreBook`，统一管理本地数据库中的成绩预览和版本。类型定义在 `src/shared/score-commands.ts`；实现位于 `src/core/score-book.ts`，差异计算位于 `src/core/score-differences.ts`。

- `preview(bytes, input)`：输入班级、考试信息、满分与科目组、逐人计分组、原始分确认、格式、文件名及显式映射/排除。返回行级问题、统计、与旧版本的差异及一次性确认令牌；不写数据库。
- `confirm(input)`：只接受 epoch、预览令牌、请求 ID、期望版本和原因。后台读取自己保管的内容，在事务中核对名册和版本，再创建考试或追加版本。
- `cancel({ epoch })`：清除待确认内容；正在解析的迟到结果也不能重新生成有效令牌。
- `list({ epoch, classId? })`：列出考试的最新版本摘要。
- `history({ epoch, examId })`：返回该考试全部版本及更正原因，按版本倒序。
- `read({ epoch, versionId })`：读取指定版本、重新计算统计，并返回最新版本 ID 与 `stale` 标记。后续报告须保存版本 ID 和科目 ID，不得只保存考试名。
- `studentHistory({ epoch, studentId, subjectId })`：按日期显示各考试最新版本中的单科记录、满分及得分率；不将更正前版本混作另一次考试。

单次版本保存整场考试的确认批次，各科以 `(versionId, subjectId)` 引用。这样导入包含多科时，可以同一事务生效而不留下部分科目更新。

## 确认规则

后台最多保管一个预览，保留 15 分钟。新预览、取消、恢复、关闭都会使旧令牌失效；错误预览不产生令牌。前端获得的行或统计被修改，不改变后台保存的不可变 JSON。

新考试使用当前班级全部在籍学生，每人必须显式分配计分组。更正已存在的考试使用该考试的历史应考名册，保留原编号、姓名和班级名，不把调班后的新成员自动补进旧考试。首期更正可以调整计分组与科目配置，但不能通过更正文件偷偷增删应考学生。

预览开始、解析结束、正式确认均检查有关名册与班级状态；确认还检查数据库中的最新成绩版本。陈旧操作拒绝后须重新预览，不静默覆盖。错误行可按现有规则排除，未上传和被排除的应考学生仍计入数据缺口。

已有成绩的更正返回逐学生、逐科目的前后值及配置差异。真实零分、缺考、未选考和未录入保持区分；不存在于某一版本范围的科目使用 `null`，不是零分。相同成绩与配置重导入（包括仅改变行列顺序）显示 `unchanged` 并禁用确认，不制造冗余版本。文件来源名称或摘要变化本身不算成绩更正。

同班级中，考试名称、日期、学年、学期、年级相同的新建请求会提示选择已有考试更正。该产品去重规则不是全国统一考试编码；确实不同的同日测评须使用可区分的名称。

## 重试与回滚

前端应在第一次点击确认前生成请求 UUID，重试同一确认时复用原请求 ID 及原命令，不生成新 ID。数据库保存请求摘要，完全相同的重试返回原版本，关闭重开仍有效；同一 ID 换令牌、原因或版本等内容会被拒绝。

确认失去响应不代表未保存。恢复当前数据后先以原命令查询式重试或检查版本历史；不能再次创建相同考试。若进程在提交前退出，整个事务回滚，内存令牌丢失，须重新预览；若在提交后退出，原请求可重放取得原回执。

考试创建和成绩版本插入位于同一 SQLite 事务。空间不足、数量超限或测试中断不会留下只有考试无成绩的半成品；历史记录不会为腾空间而删除。`transaction` 检查 `db.isTransaction` 后再回滚，保留 SQLite 已自动回滚时的原始容量错误。

## 历史口径

得分率使用该次考试的满分，以整数计算并在展示处四舍五入至两位百分数；零分为 `0.00`，缺考、未录入和未选考不返回数值。历史按稳定科目 ID 关联，不按相似名称猜测英语、其他外语或自定义科目等价。界面须沿用稳定科目 ID，而不是每次建立考试都随机重建同名科目。

报告说明试卷难度与参照群体可能变化，分数或得分率变化不能直接证明能力变化；有效考试不足两次时不生成趋势结论。当前只返回确定性描述，不调用模型。
