## 数据边界

`prepareExplanation` 只接受 `ScoreBook.read` 在后台取得的版本，不能把 Renderer 提交的成绩 payload 当作依据。教师选择班级或单个学生、科目与指标；未知学生/科目、重复选择、班级/学生指标混用以及过期版本被拒绝。

本地保留版本 ID、考试 ID、选择范围、科目真实名称、字段标签和请求摘要。出站 `wire` 只有格式版本、班级/学生范围、`F001` 等事实 ID、`S01` 等科目代号、指标键和本地计算值。它不含姓名、学生编号、班级名、考试名、日期、原始表格、分组名、文件名、自定义科目名或本地 UUID。去标识化不等于绝对匿名，少量统计仍可能有重新识别风险。

不暗中增加教师未选择的数据。派生指标的必要口径必须显式选择，否则拒绝准备：

| 指标                         | 必需口径                   |
| ---------------------------- | -------------------------- |
| 均分、中位数、最低分、最高分 | 满分、有效成绩人数         |
| 达标率                       | 目标线、达标人数、有效分母 |
| 学生成绩                     | 满分、成绩状态             |
| 学生得分率                   | 满分、学生成绩、成绩状态   |

缺失值保留 `null`，不能补零。真实零分与缺考/未录入/未选考区分。计分组只定义总分范围，缺少某科条目仍是未录入，不能自动推断未选考。

## 模型输出边界

提示词版本为 `score-explanation-v1`。输出必须是严格 JSON，最多 64 KiB：

- `observations` 只允许已有事实 ID 和逐类型一致的值；未知、重复引用或数值改写整份拒绝。
- `interpretations` 是未核实的模型补充，必须有引用及不确定性说明。
- `questions`、`actions` 是教师核实问题和未执行的建议，必须引用本地事实。
- `limitations` 必填。缺少题目级信息不得声称知识点诊断；不得以总分推断品德、心理状态、升学概率或已执行措施。

**当前校验器不证明自然语言语义真实。** 自由文本即使引用有效 ID，也可能包含错误推测或错误数字；测试专门保留反例，防止把结构/引用通过宣传为语义核验。后续页面必须把本地事实与未核实补充分区，固定显示教师审核说明，不把模型文字写回正式成绩或自动转成正式成长条目。事实展示应从本地 packet 构造，不直接显示模型改写的“事实文字”。

生成 Adapter 拒绝未正常结束的响应，包括被长度限制截断的内容；保留响应 ID、模型和用量，未知用量不能冒充零。出现失败需用户显式重试；调用可能已经收费，不能自动重复提交。

## 草案存储与恢复

`Workspace.explanations` 是唯一草案业务入口，`ExplanationBook` 不调用网络，不写成绩表。它负责准备、认领生成任务、完成、读取、列表、编辑、丢弃和取消。Main/worker 集成时必须保留这些边界：

- 准备只接受已保存的来源版本和教师选择，令牌有效 15 分钟；不写入草案。准备新任务会清除旧任务，即使新选择无效。
- `claim` 绑定唯一请求 ID，不允许重复认领，认领后期限为 2 分钟。Main 仍须执行 60 秒网络截止及取消；本地令牌不是网络取消机制。
- 完成只接受内部 worker 命令，不可暴露给 Renderer。后台复查 epoch、任务令牌、请求 ID、来源是否过期及输出引用。保存成功才清除准备状态。
- 同一完成命令的重试可在重开后返回已有记录；不同输出复用请求 ID 被拒绝。尚未完成的任务不会跨进程重开恢复或自动重发。
- 原始结构化模型输出、服务商响应信息、来源版本、选择、提示词版本及事实包哈希保存在不可编辑区域；教师只改四段编辑内容。这里的“原始输出”是通过验证的结构化结果，不保留 HTTP 正文或未经验证的响应。
- 编辑、丢弃使用 revision 防止旧页面覆盖；重复提交相同编辑或相同丢弃可幂等返回。编辑不是完整历史版本库，仅保留当前教师稿、不可变模型原稿及最新 revision。
- 丢弃为保留记录的状态变化，默认列表隐藏，可在内部查询中显式包含；不释放数量额度，也不删除对应成绩。每个数据库最多 1000 份草案，单份 payload 最多 512 KiB，仍受全库 64 MiB 上限约束。
- 成绩更正后，旧草案仍按历史版本展示事实并标记过期；不能把旧版本用于新生成。新版本的重新生成产生新草案，不覆盖旧稿。

事实包在准备时序列化为私有副本。备份校验按来源排序，对同一历史来源只解析并计算一次，切换来源便释放旧缓存；学生/科目查询使用该来源的索引。列表按来源缓存考试名称和是否过期，避免每份草案重复解析成绩 JSON。这些缓存仅用于当前操作，不信任调用者提供的统计对象，也不跨操作复用。

Schema 3 新增 `explanation_drafts` 及来源索引。v1/v2 只读打开保持原文件不变；可写升级前验证旧结构、记录和附件，保留 `.before-v3-<UUID>.sqlite` 副本，然后在事务中添加结构。v1 直接补齐成绩与草案结构，v2 只添加草案结构。新备份标记版本 3；v1/v2 备份仍可只读预览，确认恢复才升级暂存副本。旧程序不能读取 Schema 3，不可直接用旧程序覆盖新数据。

恢复预览新增草案数量，包含已丢弃草案。恢复成功会使旧 `ExplanationBook`、旧 epoch 和未完成任务失效。数据库校验同时检查草案来源、初始内容、时间顺序、丢弃状态、输出事实引用与事实哈希；重新计算备份外层哈希不能绕过这些校验。上述检查是结构和业务一致性验证，不是对被恶意整体重写的数据提供数字签名认证。

## 生成编排与接口

第三阶段新增 `src/main/explanation-runner.ts`。Main 持有解密后的 Key 和网络请求；worker 仅处理短期准备、认领和本地提交，网络等待不占用 worker 队列。公开接口新增 7 个：`prepareExplanation`、`generateExplanation`、`cancelExplanation`、`readExplanation`、`listExplanations`、`editExplanation`、`discardExplanation`。总计 33 个具名接口；`claimExplanation`、`completeExplanation` 仅为内部 worker 命令，不进入 Preload。

生成只提交 epoch 与准备令牌，请求 ID 由 Main 创建。worker 返回其私有事实包；Renderer 不能提交模型正文、响应元数据、任意提示词或替换来源数据。连接检查与解释生成共用单任务准入限制；取消后仍等旧调用结算，不通过立即清空任务槽重叠发起付费请求。

换 Key、删除 Key、成功恢复工作区会使在途解释失效。Main 与 worker 通过仅内部传递的 4 字节 `SharedArrayBuffer` 协调取消：0 表示待提交，1 表示取消，2 表示已经获得提交资格。Main 用原子比较交换取消；worker 在事务写入后、COMMIT 前原子争取提交资格。取消先发生则整个事务回滚；提交资格先获得则后续取消不撤销该草案。页面应以最终返回和重新读取结果为准，不把点击取消显示为“保证未保存”。这不是跨数据库与账本的分布式事务。

账本新增 `score_explanation`。网络发起前必须落盘 `in_progress`；写入失败不发送请求。已知响应的用量即使因取消、输出引用校验或保存失败也会累计；截断输出异常携带经过密钥脱敏的响应 ID、模型和用量，但不携带正文。没有收到可靠 usage 时保持未知，不把累计已知 Token 当作服务商完整账单。终态完成重复通知不再重复累计。

草案已提交但账本完成写入失败时，调用返回错误，草案仍存在；重新读取草案列表，不能自动重发请求。原令牌不会再次发起网络请求。重开将未结算账本标为 interrupted，其实际计费需核对服务商账单。账本不随班级备份回退，避免恢复旧班级数据抹去已发生的调用。

本阶段新增真实数据 worker 与 Main 分发测试，传输层均为合成替身。桌面脚本新增独立合成 transport，运行真实 Main、Preload、worker、OS 凭据加密与 SQLite 的生成/编辑/丢弃/备份/重开链路；没有真实服务商调用，也不是教师解释页面点击验收。
