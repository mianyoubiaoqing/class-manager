# 确认后自动继续

2026-10-03：协议更新为 `business-agent-v7`。本次修复确认正式操作后必须再发消息才能继续的停滞问题；免安装与外部办公软件扩展只调研，见[方案研究](../planning/portable-and-office-integration-research.md)。

## 原因与修复

旧版 `ConversationRunner.execute()` 只有同一模型回复中还有排队操作时才继续；单个操作或最后一个排队操作确认后直接结束，成功回执没有触发模型再次规划。最小回归测试在旧行为下观察到模型请求数为 1，而期望写入确认后自动读取及下一步提议，共 3 次请求。

现在每次成功确认都会刷新工作区，把脱敏回执及最新上下文交回模型，继续原始任务。无需输入“继续”；下一项正式操作仍展示实际内容并独立确认。已执行动作 hash 再次确认不重放写入。取消文件选择或恢复工作区后停止后续规划；失败或回包不明的操作不自动重试；单轮模型往返预算仍为 16。

等待提交后的快照期间保持 `planning`，Renderer 不会把中间状态误认为最终完成；刷新后检查原取消信号，防止创建新控制器时丢失取消。自动继续网络失败或取消仍保留已提交结果。

新对象登记到隐私映射后，重新脱敏 Main 中的工具与对话历史，避免新建班级真实名称出现在后续模型请求。界面保留教师核对所需的本地实际内容。
