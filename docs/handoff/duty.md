## 规则与口径

`src/shared/duty.ts` 定义严格运行时契约；`src/core/duty.ts` 是分组、排班与冲突校验的唯一实现，不依赖模型或设备。

- 教师明确选择参与学生、日期、组数和岗位；不推断校历或节假日。按所选成员顺序依次分组，人数差最多 1 人；不是随机分组，不承诺跨期个人工作量公平。每名参与学生恰属一个当期组，下一期独立生成组标识。
- 日期使用真实日历日期 `YYYY-MM-DD`，输入须唯一且升序；不将日期转换为 UTC 时间点。岗位在同一天内以开始/结束分钟表示，区间为前闭后开，相邻时段不冲突；跨午夜安排需拆成两个日期，不隐式跨日。
- 小组按保存顺序在日期列表轮换。岗位生成按开始时间稳定排序，从当日组选择可用成员，输出保持教师岗位顺序。同一时段不得重复占岗；不同时间可以再次安排。只统计各组值日次数与每人岗位次数，不把不同岗位、人数或时长等同为公平劳动量。
- 岗位人数不足保留明确空位并返回日期、岗位和缺口数量；不自动借用其他组成员。有空位、空组或缺日期的方案不可确认。
- 临时替换显式标记，允许选本期其他组成员，但只改变指定日期、岗位和位置，不自动交换、重排或跨期补班；仍检查缺席和时间冲突。
- 当日不可用名单按整日处理。新增不可用成员会清空其当日岗位并显示缺口；恢复可用不会擅自重新填位。未来若需要部分时段缺席，应修改领域契约和相应校验，不在页面绕过。
- 手工调整分组保持每人恰好一组；当期修订保留组标识及数量。分组调整会重建可编辑日期的岗位，清除这些日期的临时替换，因此页面必须预览并提示后再由教师确认。更改组顺序不自动轮换，显式 `rotateDuty` 才重建日期安排。
- `participantIds` 是当前名单，`members` 是当前及历史仍引用的成员快照；`changeDutyParticipants` 允许当期新增/移出学生并重新分组。新增学生须由后台核对本班有效名册，已有姓名编号快照不能改写。移出成员后，只重建可编辑日期；过去记录仍保留其姓名与安排，完全不再引用的快照才移除。
- 每日保存组名和组员快照。日期早于后台提供的本地日期，或已显式标为完成，均禁止更换岗位/组员/不可用名单；已完成不能重新开启。过去日期仅允许补记“完成”，不能补造或修改安排。未来日期不能提前标完成。
- `requireNewDuty` 用于首次确认；`requireDutyRevision` 比较权威旧版本与新版本，保护已完成/过去日期，并核对可编辑日期与当前组快照一致。当期修订保留本期日期及岗位定义，参与名单可增删，但已有成员的姓名编号快照和冻结日期不可改写。所有历史版本均须不可变保存。

当前上限：400 名当前参与学生、1000 份含已移出学生的历史成员快照、100 组、366 个明确日期、20 个岗位，每日岗位人数总和最多 400。值日周期不是固定一周；日期可不连续。空名册、无日期、无岗位、重复或未知身份、非法时间均拒绝。上限必须与后续存储体积、恢复校验及界面保持一致，不能先允许确认再导致无法重开。

## 接口维护

所有公开函数先运行时校验并返回脱离输入引用的结果，不原地修改。结构问题抛出 ZodError；规则问题抛出 `DomainError('VALIDATION', 中文消息)`；边界继续使用现有 `publicError`，不能泄露输入或路径。规则不做数据库写入、付费调用、文件导出或打印。

`inspectDutyDraft` 返回完整度、缺口、组次数与成员岗位次数；`requireCompleteDuty` 是确认及打印前的完整性门槛。`generateDuty` 仅注入组 UUID 工厂用于测试，分配本身确定且可复现。更改输入顺序会改变新方案，不能用重复生成充当失败重试。

## 后台存储阶段

`Workspace.duties` 通过 `DutyBook` 保存每期不可变版本。`prepare` 只接收班级、当前参与者 ID、日期、岗位及组数，成员名称由后台读取；`latest` 复制指定计划最新版本，允许随后移除已停用/转班学生。`adjust` 接受具名变化，成功后轮换令牌；15 分钟私有草案不得由 Renderer 整体覆盖，名册、epoch 或最新修订变化后拒绝继续确认。无效的新建请求会撤销旧草案。

确认在单个 SQLite 事务内复核完整性、冻结日期、当前名册、版本、配额及所有计划的最新安排。相同请求 ID 和参数在丢回复/重开后返回同一版本；不同参数复用 ID 拒绝。取消不删除已确认版本。跨计划冲突按学生身份、日期及岗位时间检查，不只检查同班，更不能把旧修订当成另一项当前任务。

Schema 5 增加 `duty_versions` 与单行 `duty_clock`。最多 500 期、1000 份版本，每份 UTF-8 payload 16 MiB；数据库仍受统一 64 MiB 上限约束。配额是上限，不承诺可以同时用满所有理论组合。按计划而不是按班级分配修订序号；计划标题、班级名称快照保持不变。

日期保护采用固定 UTC+08:00 中国日历日期，不依赖电脑的显示时区。启动工作区、草案写操作及确认会抬高持久化日期下界，即使后续编辑失败也不回退。过去/已完成日期不可因系统时钟回拨重新开放；确认时重新检查午夜跨日。恢复到新工作区前，先抬高原工作区下界，再把该下界传入候选库；失败后原库仍保留保护。只读旧库/恢复预览不改写日期。

数据库打开与备份恢复验证完整版本链、历史成员归属、每期修订约束、日期下界及跨计划冲突。新出现成员在该确认时须属于本班；已移出当前名单但仍被历史引用的快照不要求现在仍在本班。名册归属结束时间在回拨时不早于已确认值日时间，避免合法历史因转班或停用变成坏数据。
