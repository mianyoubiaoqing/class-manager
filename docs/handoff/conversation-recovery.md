# 对话工具错误恢复

2026-10-04。协议 `business-agent-v9`，Schema/业务备份11、管理接口140项不变。本说明取代旧版本中“工具参数错误直接终止整轮”的行为；会话管理和教师界面简化保留。

## 原因与修复

截图中的“工具参数不是完整JSON，尚未执行”来自 `conversation-response.ts` 的参数解析。最小确定性测试以完整供应商响应中的不完整工具参数驱动真实 `ConversationRunner`，旧实现首次解析失败即抛到外层，模型没有收到错误，无法修正。流式分块、UTF-8和交错批次拼接已有测试正常；无法由截图确认实际供应商是否截断了参数，因此同时覆盖非法JSON、schema错误、未知工具和长度截断。

解析仍严格，不猜补JSON。整批校验不通过时本批工具均未执行，每个调用均收到对应的脱敏错误回执；模型可重新读取参数和前置事实后修正。自动读取/临时草案失败也进入恢复循环，依赖该失败的后续操作返回未执行回执并重新规划。

成功的相同读取复用回执。分页/展示路径填错时给出已取得数据的结构，修正选择后从缓存取数据，避免重复草案调整。重复成功调用消耗恢复预算，以免无进展循环。

临时草案调整或失败后更新读取缓存代次。旧座位/值日句柄不能因缓存而继续被视作有效；句柄过期等明确业务拒绝也会回传模型，允许使用最新草案重新读取。新增真实座位草案测试先证明旧缓存错误地返回成功，再验证修复后报告旧句柄过期并读取最新50个座位。

正式操作经业务层明确拒绝（校验、版本冲突、对象不存在或未接入）时立即回传模型，修正后的方案生成新确认哈希，仍需教师重新核对并点击确认。已有成功回执的操作不会重放；正式操作的工作进程、存储或超时错误仍视为结果不明并停止。临时草案回执不明允许阅读核对，并禁止本任务重复相同修改。

## 运行边界

- 每任务最多4次自动修正，跨正式确认继续共享；模型请求仍最多16次，批次最多8调用。修正请求独立记用量，不无限重试。
- 只对白名单业务/工具错误恢复。取消、工作区/对象来源/模型配置变化、认证或网络传输失败仍停止；网络请求不会原样自动重发。
- 完整原生调用及回执进入模型前统一检查数量、顺序和ID配对。未闭合批次、孤立回执、错ID或用户消息插入批次均在传输前拒绝。
- 未完整的工具参数不回显；有效参数和错误提示经统一脱敏，回执包含执行状态及修正建议。教师界面只展示修正进度和自然语言结果，无原始JSON/上下文/推理入口。
- 达恢复上限显示明确暂停原因，保留已经完成的业务结果；不把暂停描述为所有操作均失败或均完成。

## 验证

原始最小复现命令：`rtk npx vitest run tests/conversation-runner.test.ts -t "agent repairs incomplete"`。修复前稳定抛出截图中的错误；修复后自动修正、读取并完成，无需教师另发消息。

回归覆盖整批拒绝/配对、截断与未知工具、临时读取失败及脱敏、重复读取缓存、展示路径修正、确认后立即重规划与重新确认、草案回执不明防重复、取消拒绝迟到响应、全任务恢复预算及下一轮历史配对。原有成功写入后网络失败、正式写入回包不明、来源/配置失效及16轮限制测试保留。

桌面脚本为DeepSeek/Kimi/豆包模拟SSE：先读功能目录，故意返回坏工具参数，模型修正后展示实际方案，点击确认执行并自动产生最终回复。真实SQLite写入恰好一次；模拟传输无外部请求。测试不证明真实供应商每次都能修正或真实教学效果。
