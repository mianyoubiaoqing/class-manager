# 对话格式错误重试与附件上传

日期：2026-10-06。

## 中断原因与修复范围

截图中的“模型传输格式无效”来自 `readConversationCompletion` 的 `INVALID_RESPONSE`。原有每个逻辑工具首次调用加5次纠错预算在已解析响应后的参数、工具准备和业务回执阶段生效；传输解析抛出的错误直接离开 `agentRequest`，由外层将本轮标为失败，绕过该预算。

已用两条失败回归复现该绕过：一次格式失败后有效响应应继续；连续格式失败应首次加5次重试后暂停。原代码分别直接返回 INVALID_RESPONSE；修复后恢复成功或精确发出6次请求后返回 TOOL_RETRY_LIMIT。失败请求仍独立登记调用账本，已完成的本地操作不重放。

另一个回归证明流式工具后续片段的可选 id/type/name/function/tool_calls 为 null 时原代码拒绝。现在将这些空元数据视为未提供，完整调用仍要求非空ID、函数名、字符串参数，并要求完成标记及DONE；没有采用半截工具调用。没有捕获用户那次供应商的原始回包，不能断言原回包一定含哪一个 null 字段。

网络、鉴权、限流及业务回包不明不被扩展为盲目重试。新增重试只针对尚未采用任何工具调用的传输格式错误。

## 附件行为

- 左下角上传按钮打开 Main 的原生文件选择框，可多选；Renderer 和模型不能提供任意路径。
- 支持 XLSX、UTF-8 CSV/TXT/MD、可提取文字的 PDF/DOCX；每个文件5 MiB、每条消息6文件、提取文字总计96000字符。超限拒绝，不默默截断。
- 表格保留原始行列及数值零，不需要先满足成绩导入的学号和计分口径；公式、复杂单元格或不支持的工作簿明确拒绝。
- PDF/DOCX 复用隔离文档解析进程，只发送文字。图片及扫描内容不自动OCR或发往视觉模型；存在图片时在附件卡片提示限制。
- 上传只本地解析；发送时按epoch和会话ID解析 Main 持有的附件令牌，经过既有脱敏边界，并加入确切请求和wireHash。文件内容标记为数据，文件里的角色声明、指令和授权说法不能充当用户请求。
- Agent 可以据附件分析、查询和准备现有具名业务操作，正式写入仍等待确切提议确认。上传不等于已完成名册/成绩入库。
- 草稿及消息持久化附件描述；提取正文留在本进程和活动会话中，不加入备份或诊断。切换会话保留草稿，重启后需要移除失效附件并重新上传。成功准备请求后清理附件缓存，确切准备正文及活动轮次仍保留内容；移除、删会话、恢复和退出也清理相应缓存。
