## 规则核心

`src/shared/seating.ts` 定义布局、成员快照、安排、锁定及运行时结构校验。当前布局范围为 1–20 行、1–20 列，最多 400 名参与成员；行列从 1 开始，第 1 行朝向教室前方。过道用不可用位置表示，不引入按身高、成绩、关系、性别或视力推断的规则。

`src/core/seating.ts` 是规则唯一入口，不依赖 Electron、数据库或模型：

| 操作                     | 约束与结果                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `inspectSeatingDraft`    | 深复制并校验；允许尚未安排完的草案，但拒绝重复成员/编号、越界、不可用占位、重复占位和无效锁定；返回缺口及完整状态 |
| `requireCompleteSeating` | 成员非空且每人恰好安排一次，才能供后续确认、历史记录校验与打印读取使用                                            |
| `randomizeSeating`       | 固定锁定成员，其余学生分配到洗牌后的空余可用位置；空余座位也参与随机，不总留在最后几排                            |
| `moveSeatingStudent`     | 已安排学生可移入空位或与未锁定学生交换；尚未安排的学生只可进入空位，不挤出已有成员                                |
| `setSeatingLock`         | 只锁定已经安排的成员；移动本人或占用其座位前必须显式解锁                                                          |
| `changeSeatingLayout`    | 使用同一套校验；缩小或封闭已占用位置会报错，不能静默丢弃安排或解除锁定                                            |

所有操作返回独立对象，不修改传入草案。调用失败时调用方应保留原草案并显示具体冲突，不能把错误转为空成功方案。空名册可作为未完成草案检查，但不能随机编排或确认。结构错误使用 ZodError，规则冲突使用 DomainError 的 VALIDATION；桌面接入时沿用现有公共错误转换，不透传堆栈。

生产随机源为 Node `crypto.randomInt`；测试通过函数参数注入固定种子的确定性序列。随机不是公平轮换承诺，不保存学生敏感属性、不调用模型。当前不提供用户指定种子的界面，也不把可复现随机算法变成持久化格式的一部分；保存的最终位置才是历史依据。随机源必须返回合法整数，其异常会传播但不改变原草案；重新生成不具备幂等性，不应自动重试。

## 存储层与后续接入

沿用现有 ScoreBook 的后台私有草案及不可变确认方式，不接收 Renderer 伪造的成员快照：

1. 后台从所选班级活跃名册建立草案，保留成员指纹和预期版本。页面只提交布局与业务操作。
2. 调整经后台执行上述规则。非法调整保留当前草案；工作区恢复、成员变更及陈旧版本必须在确认前拒绝。
3. 确认生成不可变版本，冻结布局版本与成员名称/编号快照；取消不修改旧确认版本。重复确认具备幂等保护。
4. 新表随 Schema、旧库迁移、备份完整性、恢复计数一并实现；不能把座位 JSON 存入未纳入备份的旁路文件。
5. 教师页面与打印使用同一确认版本。打印由平台层负责，禁止任意路径或 HTML 跨 IPC；排版、长姓名、窄窗口、分页和打印取消都需实际验证。

上述第 1–4 步已实现，第 5 步待接入。06 整体验收前不进入 07。

`Workspace.seating` 的 `SeatingBook` 保管单个 15 分钟有效的私有草案。页面只提交业务操作，不提交成员快照。成功调整轮换令牌，非法调整保留旧草案，新的准备请求先撤销旧草案；恢复或关闭工作区会销毁草案。名册指纹包含有效归属记录，成员、名称、归属变化和确认版本冲突均拒绝继续确认。随机调整不自动重试。

确认要求完整安排，在单个事务内写入不可变 `seating_versions`。请求 ID 与请求哈希用于幂等重试，包括提交成功但响应丢失后的重开重试；复用 ID 而改变参数会拒绝。每班 revision 连续增长，最多保存 1000 个版本，每份载荷最多 256 KiB。不改变布局时复用布局版本 ID，改变时生成新 ID；布局与成员名称、编号直接冻结在版本中。

历史读取不替换成当前姓名。恢复校验不仅验证学生身份存在，也验证确认时属于该班的历史归属时间区间；后来转班或改名仍允许读取原方案。同毫秒转班边界允许历史记录，确认时间不早于班级、成员、有效归属及前一版本时间，以防本地时钟回拨产生无效记录。

当前 Schema 为 4，新备份协议为 v4；v1/v2/v3 只读检查不升级，可写打开先校验并保留 `.before-v4-*.sqlite` 副本，再事务升级。旧备份仅在独立恢复副本上升级。恢复预览增加座位版本数量，替换警告明确包含座位历史。未知结构和损坏载荷仍拒绝，不通过清空数据库修复。

本阶段修复了双轴审计发现的历史归属校验、恢复警告遗漏及 v3 夹具依赖当前生产器问题。v3 夹具现使用冻结 SQL 与字面量 JSON。随后复现“确认后回拨再转班/停用”会使历史归属校验失败：两个新增测试先失败，再修复 `Workspace.membershipTimestamp`。结束归属时间以曾属班级的座位确认时间聚合值为保守下界，不解析全部历史 JSON，不改写旧方案。

## 桌面接口与教师页面

新增六个受限接口，仍只暴露冻结具名桥接，不允许 Renderer 传入成员快照、SQL、文件路径或任意通道。Main 校验窗口来源、请求大小，四项草案写操作占用本地写入槽；worker 再按严格共享 Schema 校验并串行执行：

| 接口                 | 后台操作                       |
| -------------------- | ------------------------------ |
| `prepareSeating`     | 当前名册新建或复制最新确认版本 |
| `adjustSeating`      | 布局、随机、移动/交换、锁定    |
| `cancelSeating`      | 仅取消对应令牌                 |
| `confirmSeating`     | 按原请求 ID 幂等确认           |
| `seatingHistory`     | 班级确认版本目录               |
| `readSeatingVersion` | 指定版本的不可变快照           |

`SeatingPage.tsx` 管理会话、异步响应序号、确认请求和错误恢复；`SeatingBoard.tsx` 只负责显示，不实现另一份座位规则。页面支持班级选择、行列配置、不可用格、随机、锁定、学生选择后点击目标调位、原因填写和二次确认。历史版本只读，复制调整始终来自最新版本。即使已有历史也能配置新草案容量；名册变化时不能偷偷沿用旧成员，须新建。

草案或请求进行中禁止页面导航、全局刷新和名册编辑；确认后读取失败明确显示“已保存但读取失败”，不会自动重发确认。确认响应丢失时保留完整原请求并冻结编辑，原请求重试不产生重复版本；取消后先读取确认历史，不把“取消成功”误称为“未提交”。调整响应丢失可能使本地持有旧令牌；取消失败后可关闭本地草案并核对历史，不尝试撤销未知新令牌。后台未确认草案仍仅在内存中，随后新建会替换它，重开或到期后不可确认。

## 指定版本打印

`previewSeatingPrint({ epoch, versionId })` 是第七个座位具名接口。只接受版本身份，拒绝 Renderer 传入路径、HTML 或成员。Main 通过 worker 读取已确认版本，持有独占写入槽直至预览关闭；预览期间不会发生工作区恢复或保存插队。

`core/seating-print.ts` 是无 I/O 的纯文档生成器，复核完整快照、转义所有用户文本。按 A4 横向、每片最多 6 列、依据最长姓名/编号计算行容量进行分片，每页带原始行列范围、确认版本 ID 及页码。列数不足时仍保留同样格宽，不任意放大或缩小姓名；每个座位及成员只出现一次。打印源不会因后续改名、转班或新版本变化而替换。

`main/seating-print.ts` 提供独立原生菜单窗口：无 Preload、关闭 JavaScript、开启 sandbox/contextIsolation、禁用 Node 和导航，内容只来自内部生成文件。菜单提供打印、PDF 导出及关闭；没有通用 IPC。PDF 使用同一 HTML 和打印分页规则，选定路径后原子写入，禁止覆盖业务数据或受管打印缓存。

打印返回状态区分关闭、已提交队列、取消、PDF 已导出、PDF 取消、失败和操作未结束。队列提交不等于实际出纸；没有自动重试。关闭在途操作会标记结果不明，必须核对系统打印队列或导出文件；已经完成但仍显示提示框的操作保留已知结果。打印次数和 PDF 数量分别累计，后续取消不会抹掉此前已提交次数。

`main/print-preview-files.ts` 在应用用户目录的 `print-previews` 管理临时文件。写入可识别标记后才写入学生文本，关闭时最多重试 3 次非递归清理；启动时只回收标记匹配的直属预览目录，不扫描通用 TEMP。未知文件、目录和符号链接不会被删除。最终目录删除失败会恢复标记，确保下次仍能识别；失败保留打印结果，同时返回清理警告。诊断只记录残留数量，不包含姓名、编号或缓存路径。强制结束进程可能暂留缓存，重启会重试回收；这不是加密备份，也不能承诺强制中断期间磁盘上没有缓存。
